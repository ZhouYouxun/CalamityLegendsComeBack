1a. BaseGunHoldoutProjectile
  File: Projectiles/BaseProjectiles/BaseGunHoldoutProjectile.cs
--------------------------------------------------------------------------------

PURPOSE:
  Abstract base class for the large majority of ranged holdout projectiles.
  Provides a unified framework for arm positioning, recoil, texture/name
  auto-derivation, and multiplayer syncing.

AI CALL ORDER (each frame):
  AI() -> KillHoldoutLogic() -> ManageHoldout() -> HoldoutAI()

ABSTRACT MEMBERS (subclasses MUST implement):
  - int AssociatedItemID        : The item type this holdout belongs to.
  - void HoldoutAI()            : All weapon logic goes here.

KEY VIRTUAL MEMBERS (subclasses MAY override):
  - Vector2 GunTipPosition      : Spawn point for projectiles.
                                  Default: Center + rotated (width*0.5) forward.
  - float WeaponTurnSpeed       : How fast the holdout rotates toward mouse.
                                  Default: 0.2f
  - float RecoilResolveSpeed    : Lerp speed to restore OffsetLengthFromArm.
                                  Default: 0.3f
  - float MaxOffsetLengthFromArm: Maximum arm extension length (no default,
                                  each subclass sets this).
  - float OffsetXUpwards/Downwards, OffsetYUpwards/Downwards, BaseOffsetY,
    BaseOffsetX: Fine-tune holdout placement.
  - void KillHoldoutLogic()     : Default calls Projectile.Kill() when
                                  Owner.CantUseHoldout().
  - void SendExtraAIHoldout() / ReceiveExtraAIHoldout(): For syncing extra
                                  local fields in multiplayer.

KEY PROPERTIES:
  - Owner (Player)              : The owning player.
  - HeldItem (Item)             : The currently held item.
  - KeepRefreshingLifetime (bool): If true (default), timeLeft is set to 2
                                   each frame.
  - SetUsage (bool)             : If true (default), sets itemTime/itemAnimation
                                   to 2 each frame (keeps weapon in use state).
  - OffsetLengthFromArm (ref float): Decreasing this creates recoil.
                                   Auto-lerps back via RecoilResolveSpeed.
  - ExtraFrontArmRotation/ExtraBackArmRotation (float): Extra arm rotation.
  - FrontArmStretch/BackArmStretch: Composite arm stretch amount enums.
  - ContinuouslyUpdateDamageStats: Always true (damage respects buffs live).

SetDefaults():
  - Width/height taken from item texture.
  - tileCollide = false, netImportant = true
  - DamageType = DamageClass.Ranged
  - ContinuouslyUpdateDamageStats = true

Texture and DisplayName are auto-derived from AssociatedItemID's item class.

SYNCING:
  - SendExtraAI/ReceiveExtraAI are SEALED; subclasses use
    SendExtraAIHoldout/ReceiveExtraAIHoldout instead.

--------------------------------------------------------------------------------
1b. BaseIdleHoldoutProjectile
  File: Projectiles/BaseProjectiles/BaseIdleHoldoutProjectile.cs
--------------------------------------------------------------------------------

PURPOSE:
  Alternative base class for "always-active" holdouts that spawn themselves
  without requiring a Shoot() call from the weapon item. Uses a static
  dictionary mapping item IDs to projectile types.

SELF-SPAWN MECHANISM:
  - Static Dictionary<int,int> ItemProjectileRelationship populated in
    SetStaticDefaults().
  - CheckForEveryHoldout(Player): iterates all registered items each frame,
    spawns the holdout if the player holds the matching item and the holdout
    isn't already alive.

AI FLOW:
  Sealed AI(): CheckForEveryHoldout() -> kills if wrong item / CCed / dead /
               profanedCrystalBuffs -> calls SafeAI() (the subclass hook).

DIFFERENCE FROM BaseGunHoldoutProjectile:
  - Self-spawning (no Shoot() override needed on the weapon).
  - Simpler; no recoil, no arm management framework built-in.
  - Used primarily by support / accessory-style ranged items, NOT by the 41
    weapon holdouts documented below.

  DelayTimer determines which beam color fires.
