## 第一部分：槽位缩放的四种数学

2.1 召唤重做里，"多召唤几次"带来的强化走了四条不同的曲线。**选哪条决定了武器的成长手感。**

| 武器 | 公式 | 类型 |
|---|---|---|
| **Sun Spirit Staff** | 每槽 **+100% 攻速** | 线性（攻速） |
| **Vengeful Sun Staff** | 每槽 **+25% 伤害 与 +25% 攻速** | 线性（双通道） |
| **Saros Possession** | 每额外槽 **+20% 伤害与攻速** | 线性 |
| **Sirius** | `damageMod = 1 + Pow(0.2f × minionSlots, 1.5f)` | **指数（1.5 次幂）** ✅ |

✅ **Sirius 的"以指数关系提升伤害"在源码里就是这行 `MathF.Pow(0.2f * Projectile.minionSlots, 1.5f)`**：

| `minionSlots` | `damageMod` |
|---:|---:|
| 5 | 2.00× |
| 6 | 2.32× |
| 8 | 3.02× |
| 10 | 3.83× |
| 12 | 4.72× |

**1.5 次幂是"超线性但不失控"的经典选择**——比线性有成长快感，又不像平方那样在高槽位爆炸。

## 第二部分：Sirius —— 槽位驱动的星座（本篇最漂亮的设计）

### 2.1 星座随槽位逐颗点亮 ⚠️

```csharp
void SpawnStar(float SlotRequirement, Vector2 offset, float intensity, int flashOffset = 0, int flashMod = 100)
{
    if (SlotRequirement > 0 && Projectile.minionSlots < SlotRequirement)
        return;                                  // ← 槽位不够就不画这颗星
    offset.X *= Projectile.spriteDirection;
    ...
}

SpawnStar(0,  new Vector2(   0f,   0f), 1.5f,   0, 300);  // Sirius（天狼星本体）
SpawnStar(2,  new Vector2(-118f, 217f), 0.75f, 40);       // bottom
SpawnStar(3,  new Vector2( -67f, 272f), 0.75f, 120);      // back foot
SpawnStar(4,  new Vector2( 119f,  32f), 0.75f,   5);      // front foot
SpawnStar(5,  new Vector2(-192f, 284f), 0.75f,  10);      // tail
SpawnStar(6,  new Vector2( -62f,  11f), 0.5f,   75);      // neck
SpawnStar(7,  new Vector2( -50f,-103f), 0.5f,  130);      // nose
SpawnStar(8,  new Vector2(-101f, -23f), 0.5f,   20);      // head
SpawnStar(9,  new Vector2(  46f,  59f), 0.5f,  100);      // front leg
SpawnStar(10, new Vector2( -49f, 166f), 0.5f,   60);      // belly
```

✅ **这是真正的大犬座（Canis Major）星座图**——源码注释逐颗标了部位名（尾、颈、鼻、头、前腿、腹）。天狼星本身是大犬座 α 星，正是 `SlotRequirement = 0` 的那颗（永远存在、`intensity` 最高 1.5）。

**槽位就是"点亮星座"的进度条**：2 槽出第一颗附属星，10 槽集齐全部 10 颗。官方说的"重复召唤可得到星座式额外星体"就是这个，**而且它有明确的解剖学顺序**，不是随机加星。

`offset.X *= Projectile.spriteDirection` —— 星座会随仆从朝向水平翻转。

### 2.2 每颗星独立闪烁 ✅

```csharp
Color.SlateBlue * ((Owner.miscCounter + flashOffset) % flashMod < 5 ? 0.75f : 1f)
```
- `flashMod` 是每颗星的**闪烁周期**：300 / 100 / 120 / 5 / 10 / 75 / 130 / 20 / 100 / 60 帧
- `flashOffset` 是**相位偏移**
- 条件成立时亮度降到 0.75 → **"眨眼"是变暗而非变亮**

⚠️ **注意 front foot 的 `flashMod = 5`、tail 的 `= 10`** —— 这两颗几乎在高频抖动，而 Sirius 本体是 300 帧一次。**周期跨度 60 倍**，所以整个星座永远不会出现"一起眨眼"的机械感。这是本篇最值得抄的一个细节。

### 2.3 星体尺寸绑 Starburst 存量 ✅

```csharp
var SiriusScale = 0.055f + (0.001f * (moddedOwner.AvaliableStarburst + value));
```
**基础 0.055，每点可用 Starburst +0.001**。满 100 点时 `0.055 + 0.1 = 0.155`，约 **2.8 倍**。
→ **星座会随资源积累整体变大变亮**，是一个不需要 UI 的资源条。

每颗星由两个粒子构成：
```csharp
new BloomParticle(pos, Vector2.Zero, Color.SlateBlue * 闪烁, 2*SiriusScale*intensity, 2*SiriusScale*intensity, 2, false);
new CustomSpark(pos, Vector2.UnitX.RotatedBy(MathHelper.Pi * (Owner.miscCounter/300f)) * 0.1f,
                "CalamityMod/Particles/Sparkle", false, 2, 10*SiriusScale*intensity, Color.SkyBlue, Vector2.One);
// 两者都 SpawnParticle(..., false, GeneralDrawLayer.AfterProjectiles)
```
- **`Lifetime = 2`** → 又是第 0 篇 §2.4 的"单帧重绘型"：每帧重新生成，靠持续刷新维持
- `BloomParticle` 的 `originalScale == finalScale` → **不膨胀**，纯粹当静态光点用
- `CustomSpark` 的 scale 是 `BloomParticle` 的 **5 倍**（`10*` vs `2*`），形成"小亮核 + 大星芒"
- 位置补偿：`- (Owner.oldVelocity * Math.Clamp(offset.Length() * 0.001f, 0, 1))` —— **离本体越远的星，跟随玩家移动的滞后越大**，制造出星座"拖曳"的惯性感

### 2.4 Starburst 产出与消耗 ✅

```csharp
// 产出（源码注释：0.33 starbursts per seconds per minion slot）
moddedOwner.StarburstSpawnFrameCounter += Projectile.minionSlots / (float)CalamityUtils.SecondsToFrames(3f);
while (moddedOwner.StarburstSpawnFrameCounter >= 1 && moddedOwner.StratusStarburst <= CalamityPlayer.MaxStratusStarburst)
{
    moddedOwner.StratusStarburst++;
    moddedOwner.StarburstEntities.Add(new StarburstEntity(Projectile.Center));
    moddedOwner.StarburstSpawnFrameCounter--;
}

// 保护衰减（第 3 篇提过：场上有天狼星就不掉）
moddedOwner.StratusStarburstResetTimer = (int)MathHelper.Max(moddedOwner.StratusStarburstResetTimer, 60);

// 触发
if (moddedOwner.AvaliableStarburst >= CalamityPlayer.MaxStratusStarburst)   // 满 100 ✅
    Projectile.ai[2]++;
// 动画收集直到 value >= 50 ✅
```
✅ **产出率 = 每仆从槽每 3 秒 1 点**（源码注释直接写了 0.33/sec/slot）。10 槽时 3.33 点/秒，30 秒回满。
✅ **满 100 触发、消耗 50** —— 与第 3 篇 Starburst 系统的记录一致。
✅ **天狼星在场就把 `StratusStarburstResetTimer` 拉到至少 60**，所以只要天狼星活着，Starburst 就不会自然衰减。这正是第 3 篇 §4.2 提到的"保护期"的来源之一。

**索敌半径 5000 像素**（`Projectile.Center.MinionHoming(5000f, Owner)`）—— 极大。

爆发时 `int dustAmt = 50;`（两处）。

## 第三部分：其余 8 把的机制要点

### Dazzling Stabber Staff / 耀目穿刺者杖 ✅
**3 把刀共占 1 个仆从位**，三种材质三套运动曲线：
| 刀 | 运动 | 护穿 |
|---|---|---|
| 水晶刀 | 高速斩击后**停顿** | 50% |
| 火焰刀 | **宽弧挥砍** | 20% |
| 岩刀 | **突进并后坐** | —（300% 伤害） |

> **可复刻要点**：这是"一个召唤位塞三个实体"的范例。关键在于**三者的运动曲线必须截然不同**（急停 / 弧扫 / 冲撞），否则会被读成"同一把刀换了色"。官方核对栏也特别强调了这点。

### Sanctified Spark / 圣耀火花
- 哨兵**跟随玩家**（旧版是定点炮台）
- **"连射—停顿"循环**开火
- **每次停顿按每 4 个仆从位生成 1 枚治疗球** → 治疗球数 = `floor(仆从位 / 4)`，**不是固定数**

### Saros Possession / 星律之握揽
- 8 槽太阳光环，持续放追踪光球
- 每个额外槽位 **+20% 伤害与攻速**
- **满槽后**改从光标发日蚀束：初始 `200% × 槽位`，**5 秒内衰减到 `100% × 槽位`**，随后等待持续时间回充
- 实体：`SarosAura`（光环）、`SarosEclipseBeam`（日蚀束）

⚠️ **200%→100% 的 5 秒衰减是本武器的核心节拍**，不能画成恒定 200%。

### Sun Spirit Staff / 太阳之灵法杖
- **最重要的视觉变化：hitscan → 实体飞行束**。官方核对栏原文："需要看到光束从仆从到敌人的飞行"
- 每个仆从位 **+100% 攻速**（纯攻速，无伤害加成）

### Vengeful Sun Staff / 复仇之阳法杖
- 同样是中速实体束
- **命中后分裂为固定 2 枚追踪光球**（不是命中闪光）
- 每槽 **+25% 伤害与 +25% 攻速**

### Virid Vanguard / 葱茏之锋
三层结构：
1. 仆从在**刀刃与斧头**攻击间交替
2. **斧头环绕玩家时造成 125% 伤害**
3. 左键且仆从槽位满时，**全部仆从对光标作 500% 弧斩，5 秒冷却**（仅在持有此杖时计时）

所有仆从施加随仆从数缩放的 **Sage Poison（50 DPS）**。

⚠️ **满槽指令不新增仆从，而是调度现有全员** —— 这是"指令型"召唤的正确做法。

### Void Eater Marionette / 虚空吞噬者傀具
**有明确轮换的三段 AI**（官方核对栏警告：不应把三套攻击同时无节制触发）：
1. 螺旋冲锋
2. 缓慢接近时高速散射火球
3. 快速传送冲锋 + 放环形小火球

无敌人时回收掉落物并搬给玩家；**Shift + 右键改拾取优先级**。
传送用 `DoGWeaponTeleportRift` 实体。

### Void Concentration Staff / 幽冥统御（2.2，6 个实体类）
- 改为 **4 槽**光环，生成绕玩家运行的暗能量
- 暗能量享 **15% 乘算减伤**
- 右键**标记目标 10 秒**：暗能量消失并射束追击
- 命中标记目标会生成额外暗能量，从 **1.3 倍**的触发攻击汇聚

三层必须分开：轨道暗能量 / 右键标记束 / 命中后汇聚的新增暗能量。旧版黑洞与常驻 +5% 召唤增伤已不再是主机制。

## 第四部分：召唤系的三条通用法则

1. **槽位是连续旋钮，不是离散数量。** 9 把里 6 把把"额外召唤"映射成强度而非数量。选线性（Sun Spirit +100% 攻速）还是指数（Sirius 1.5 次幂）决定了成长曲线的手感。

2. **"满槽"应该解锁一个质变，而不是继续堆量。**
   - Saros Possession：满槽 → 日蚀束（新形态）
   - Virid Vanguard：满槽 → 全员指令弧斩（调度而非新增）
   - Sirius：满 Starburst → 40 倍瞬移光束

3. **视觉强度应绑资源而非绑时间。** Sirius 的星体尺寸 `0.055 + 0.001 × Starburst` 是全篇最好的例子——玩家看星座大小就知道资源存量，完全不需要 UI。
