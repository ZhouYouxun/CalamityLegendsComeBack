## 1. Anahita's Arpeggio / 阿娜希塔琶音 / 魔法

**这是全篇状态机最清晰的一把，用它作为魔法系的教学样本。**

### 三状态机（`AIState` = `Projectile.ai[1]`）

```
AIState 0：绕身储音   →  AIState 1：淡出转场   →  AIState 2：光标同心收束
```

### 状态 0 — 绕身 ✅
```csharp
Projectile.timeLeft = LingeringTime + FadeOutTime;    // 300 + 20，每帧重置 → 持续按住不死

float baseRotationSpeed = 1f;                          // GFB 世界是 0.857142f (= 6/7)
float rotationSpeed = baseRotationSpeed * (60f / Owner.HeldItem.useTime);
Projectile.Center = Owner.Center + new Vector2(80, 0).RotatedBy(MathHelper.ToRadians(Timer * rotationSpeed));
```
- **轨道半径 = 80 像素** ✅（官方"轨道半径未公开"）
- **角速度与武器 `useTime` 反相关**：`60 / useTime` 度/帧。武器越快，音符转得越快。这保证了"攻速加成"能被看见。
- `CanDamage() => AIState == 2f` —— **绕身期完全无伤害**，纯蓄势

**尺寸呼吸**（贯穿所有状态）：
```csharp
if (localAI[0] == 0f) { scale += 0.02f; if (scale >= 1.15f) localAI[0] = 1f; }
else                  { scale -= 0.02f; if (scale <= 0.85f) localAI[0] = 0f; }
```
在 **0.85 ↔ 1.15** 间以 0.02/帧往返 → **周期 30 帧（0.5 秒）**。这是最简单的呼吸实现（状态机而非 sin），好处是不需要额外的相位变量。

**音符数上限 6** ✅ 由释放期的角度间隔决定（见状态 1）。

**每颗音符有自己的音高**：
```csharp
if (Timer == 1f)
    SoundEngine.PlaySound(new SoundStyle("CalamityMod/Sounds/Item/HarpLV" + Math.Clamp((int)NoteSequence + 1, 1, 6)) with { Volume = 0.8f }, Owner.Center);
```
`HarpLV1` ~ `HarpLV6`，由 `NoteSequence`（`ai[2]`）决定。**6 个音符 = 6 个不同的竖琴音，连续召出就是一段琶音**——武器名的由来，也是它最重要的"特效"：**听觉特效**。

### 状态 1 — 淡出转场 ✅
```csharp
// 只设置一次向外的速度
playerDirection.Normalize(); playerDirection *= 5.5f;
Projectile.velocity = playerDirection;

Projectile.alpha += (int)Math.Ceiling(255f / FadeOutTime);   // 20 帧内 alpha 0→255
if (Projectile.alpha >= 255) {
    float degreesAmt = 60f;                                   // GFB 是 51.428f (= 360/7)
    Vector2 offset = Vector2.UnitY.RotatedBy(MathHelper.ToRadians(60f * NoteSequence) + _randomReleaseRotationOffset);
    Vector2 mouse = Owner.ClampedMouseWorld();
    Projectile.Center = mouse + offset * 220f;                // 重现在光标周围 220 像素
    ReleaseCenterPoint = mouse;
    Projectile.velocity = (Projectile.Center - mouse).SafeNormalize() * -13f;   // 朝内 13
    SoundEngine.PlaySound(AnahitasArpeggio.EndSound with { Volume = 0.8f }, Projectile.Center);
    AIState = 2f;
}
```
✅ **关键数值全部确证**：
- 淡出用时 **20 帧**（`FadeOutTime`），向外速度 **5.5**
- **`degreesAmt = 60f` → 360/60 = 6，这就是"最多 6 音符"的几何根源**
- 重现半径 **220 像素**，向内初速 **13**
- `_randomReleaseRotationOffset` 是网络同步的随机整体旋转 → **每次释放的六边形朝向不同**

**为什么要先淡出再瞬移？** 因为如果直接把音符从玩家身边"飞"到光标，路径会很长很乱。淡出 20 帧 + 瞬移 = **视觉上的转场剪辑**，干净利落。这是很电影化的处理。

### 状态 2 — 收束与追随 ✅
```csharp
// 淡入/淡出
if (Projectile.timeLeft > 30) { alpha -= 17; }   // 15 帧内淡入
else                          { alpha += 9;  }   // 最后 30 帧淡出

// 减速
if (Projectile.velocity.Length() > 0.5f) Projectile.velocity *= 0.925f;
else {
    Projectile.velocity = Vector2.Zero;
    // 缓慢追随光标
    Vector2 dir = (mouseWorld - ReleaseCenterPoint).SafeNormalize(Vector2.Zero);
    float distToMove = MathF.Min(5.75f, Vector2.Distance(mouseWorld, ReleaseCenterPoint));
    ReleaseCenterPoint += dir * distToMove;
    Projectile.Center   += dir * distToMove;
    // 绕中心缓慢旋转
    Projectile.Center = ReleaseCenterPoint
        + Utils.DirectionTo(ReleaseCenterPoint, Projectile.Center).RotatedBy(MathHelper.Pi * 0.01f)
          * Vector2.Distance(ReleaseCenterPoint, Projectile.Center);
}
```
✅
- **最大追随速度 5.75 像素/帧** —— 官方"随后旋转缓慢靠光标"的确切上限
- **旋转 `π * 0.01` 弧度/帧 = 1.8°/帧 → 200 帧（3.33 秒）转一圈**。确实是"缓慢"
- 减速系数 `0.925`（从 13 降到 0.5 约需 42 帧）
- **注意 `Projectile.Center` 的旋转是"保持到中心距离不变、只转角度"** —— 用 `DirectionTo(...).RotatedBy(...) * Distance(...)` 而非直接加速度。这保证半径**绝对不会漂移**，六个音符永远在完美的同心圆上。这是做"稳定轨道"的正确写法。

### 视觉构成
- **`TrailCacheLength = 4`、`TrailingMode = 0`**，`PreDraw` 走 `DrawAfterimagesCentered(Projectile, 0, lightColor, 1)` —— 仅 4 段残影，非常克制
- **光照**：`Lighting.AddLight(Center, 0f, 0f, 1.25f)` —— **纯蓝，红绿为 0**。这是全篇最"单色"的光照之一
- `penetrate = 5`、`localNPCHitCooldown = 16`
- 命中：`BuffID.Wet` 900 帧 + `BuffID.Confused` 300 帧
- 命中音效走 `SingularSoundInstanceSystem.PlaySingleInstance(HitSound, 60, 60, Owner)` —— **单实例限流**，避免 6 个音符同时命中时音效叠成噪音

> **可复刻要点**：`SingularSoundInstanceSystem` 值得专门学。任何"多实体同时命中"的武器都需要它，否则音效会爆掉。

### GFB（`Main.zenithWorld`）彩蛋
- 音符数变 **7**（`degreesAmt = 51.428f = 360/7`），转速变 `6/7`
- 颜色按 `NoteSequence` 变成七彩虹：`(255,0,0) (255,128,0) (255,255,0) (0,255,0) (0,255,255) (0,0,255) (128,0,255)`
- 光照变白 `(1.25, 1.25, 1.25)`
- 播放 `SevenTrebleClefSouls`（源码注释：*"Big shoutouts to NotRyo for making this Finale remix out of harp notes"*），每 **2428 帧**循环一次
- 源码注释另有一句 `// They did not obey me`

## 2. Phantasmal Fury / 幻象之怒 / 魔法

### 两阶段状态机（用 `time` 而非 `ai[]`）

```csharp
Projectile.extraUpdates = 5;          // MaxUpdates = 6
Projectile.timeLeft = 900;
Projectile.ArmorPenetration = 15;
Projectile.localNPCHitCooldown = 16 * Projectile.MaxUpdates;   // = 96 子帧 = 16 实帧
```

### 阶段 A：绕身蓄势（`time` 15 ~ 500）✅
```csharp
Vector2 circle = Owner.Center + new Vector2(0, -30).RotatedBy(time * 0.05f);
Vector2 moveToEnemy = (circle - Projectile.Center).SafeNormalize(Vector2.UnitX);
if (Projectile.velocity.Length() < 8)
    Projectile.velocity += moveToEnemy * Main.rand.NextFloat(0.2f, 0.4f);
else
    Projectile.velocity *= 0.85f;
```
- **轨道半径仅 30 像素**（官方"环半径未公开"）—— 非常贴身
- **注意这不是硬性定位，而是"追逐一个旋转的目标点"**：魂用加速度（`+= 0.2~0.4`）追向 `circle`，速度上限 8。因为是柔性追逐，多个魂会自然地形成松散的、有惯性的漩涡，而不是僵硬的等距圆环。**这与 Anahita 的硬性定位形成鲜明对照。**
- `time * 0.05f` 弧度/子帧，`MaxUpdates = 6` → **实际 0.3 弧度/帧**，约 21 帧转一圈

### 阶段 B：齐飞索敌（`time >= 500`）✅
```csharp
if (time == 500) { Projectile.penetrate = 1; launched = true; }
if (targeted == null || targeted.life <= 0) targeted = Projectile.Center.ClosestNPCAt(950);
CalamityUtils.HomeInOnSelectedNPC(Projectile, targeted, true, 0.15f, 6, 0.98f, accelerate: true);

if (time < 550 && targeted == null) {
    if (Projectile.velocity.Length() < 6)
        Projectile.velocity += (mouseWorld - Projectile.Center).SafeNormalize(UnitX) * 0.35f;
    else
        Projectile.velocity *= 0.9f;
}
```
**`time = 500` 是子帧计数**，`MaxUpdates = 6` → **实时 500/6 ≈ 83.3 帧 ≈ 1.39 秒** ✅ 精确对应官方"1.38 秒后齐飞光标再索敌"。

- 索敌半径 **950 像素**
- 无目标时先朝光标加速（上限 6），**只在 `time < 550`（额外 50 子帧 ≈ 8 帧）内有效** → 短暂的"朝光标冲"窗口，之后完全交给索敌
- `penetrate` 从 `-1` 变 `1` —— **绕身期无限穿透，发射后只能打一个**

### 伤害与击退的两档 ✅
```csharp
modifiers.SourceDamage *= (launched ? 1f : 0.3f);                       // ✅ 官方 30%

Vector2 launchVel = (Owner.Center - target.Center).SafeNormalize(UnitY) * -10 * (launched ? 0.5f : 1);
target.MoveNPC(launchVel, 10 * (launched ? 0.5f : 1), true, Owner);
```
✅ **绕身期 30% 伤害 + 全额击退（10）；发射后 100% 伤害 + 半额击退（5）。**
官方说"30% 伤、双击退"——"双击退"指的是相对发射态的 2 倍。**击退方向是"从玩家指向敌人"的反向乘 -10，即把敌人推离玩家。**

`CanHitNPC` 覆写：锁定目标后**只能打锁定的那个**（`target == targeted ? null : false`），防止贴身魂群误伤路人。

### 视觉 ✅
- `Main.projFrames = 4`，每 5 帧换一帧（`frameCounter > 4`）
- `TrailCacheLength = 6`、`TrailingMode = 2`
- `Lighting.AddLight(Center, Color.White * 0.5f)`
- **公转 dust**（`time > 5` 起，每子帧 1 个 → 每实帧 6 个）：
  ```csharp
  dustRotation += 0.12f;      // 每子帧
  Vector2 dustPos = Center + (MathHelper.Pi + dustRotation + MathHelper.PiOver2).ToRotationVector2() * 10f * scale;
  Dust dust = Dust.NewDustPerfect(dustPos, DustID.SpectreStaff,
                                  (MathHelper.Pi + dustRotation * Math.Sign(velocity.Length())).ToRotationVector2() * 2);
  dust.noGravity = false;
  dust.scale = rand(0.75, 1.2);
  dust.alpha = rand(100, 171);
  ```
  **dust 在弹体周围 10 像素的圆上按 `dustRotation` 公转**，每子帧转 0.12 弧度 → 每实帧 0.72 弧度，约 8.7 实帧转一圈。因为生成点在旋转，dust 轨迹会拉成一条**螺旋线**而不是圆环。
  `noGravity = false` —— **幽魂尘会往下掉**，这与"幽灵"的飘散感一致。

> **可复刻要点**：Anahita（硬定位、稳定六边形）和 Phantasmal Fury（柔性追逐、松散漩涡）用了两种截然相反的环绕实现。**选哪种取决于你要的是"仪式感"还是"生命感"。** 这是本篇最重要的对照。

## 3. Vitriolic Viper / 酸蚀毒蝰 / 魔法

### 双段蓄力状态机 ✅
```csharp
public int FirstChargeFrames   = 30;      // 第一段：30 帧 = 0.5 秒
public int FullyChargedFrames  = 30;      // 第二段：再 30 帧
private bool FirstCharge => CurrentChargingFrames   >= 30;
private bool FullCharge  => CurrentOverchargeFrames >= 30;
```
**30 + 30 = 60 帧 = 1 秒** ✅ 精确对应官方"蓄 1 秒"。但注意这是**两段**而不是一段——第一段满了之后 `CurrentChargingFrames` 停止、改由 `CurrentOverchargeFrames` 计数。

两个强度变量：
```csharp
chargePower = Utils.GetLerpValue(0, 30, CurrentChargingFrames, true) * (FullCharge ? 1.4f : 1);
// 满蓄时整体 ×1.4 → chargePower 可达 1.4

if (CurrentOverchargeFrames < 30)
    overchargePower = MathHelper.Clamp(Utils.GetLerpValue(60, 0, CurrentOverchargeFrames, true), 0.5f, 1);
else
    overchargePower = MathHelper.Lerp(overchargePower, 1, 0.09f);
```
⚠️ **`overchargePower` 在第二段是 `GetLerpValue(60, 0, ...)`——从 1 递减到 0.5**，满蓄后才 lerp 回 1。所以视觉上第二段会先"收缩"再"回涨"，制造一个蓄力的呼吸感。

### 唾液模式（未满蓄）✅
```csharp
Projectile hiss = NewProjectileDirect(..., shootVelocity * Clamp(chargePower, 0.3f, 1),
                                      ProjectileType<VitriolicViperSpit>(),
                                      (int)(Projectile.damage * Clamp(chargePower, 0.3f, 1)), ..., chargePower);
hiss.extraUpdates = (int)(Utils.Remap(chargePower, 0, 1, 2, 13, true));
```
- **伤害与初速都 = `chargePower`（下限 0.3）**
- **`extraUpdates` 从 2 涨到 13** → 实际飞行速度是 3 倍到 14 倍。**这是"散布随蓄力收紧"的真正实现方式**：不是改角度，而是**改速度**。速度越快，同样的角度偏差在到达目标时的横向偏移越小，视觉上就"收紧"了。⚠️ 这个技巧很反直觉但非常有效。
- 枪口：17 个 `DustID.FireworksRGB`（速度 `rand(5,25)`，scale `rand(0.55,0.75) * chargePower + 0.1f`，色 `Lerp(White, 1/4概率 Green : Chartreuse, 0.7f)`）+ 1 个 `GlowSparkParticle(GunTip, 方向*18, false, 6, 0.057f * chargePower, bColor, new Vector2(1.7f, 0.8f), quickShrink: true)`
- `OffsetLengthFromArm -= 15`
- 音效 `ViperSpit`，`Pitch = chargePower * 0.3f ± 0.1`

### 满蓄：33 尖牙 ✅
```csharp
// 源码注释原文：// Vipers can apparently have 33 teeth or something like that
for (int i = 0; i < 33; i++)
    Projectile.NewProjectile(..., GunTipPosition,
        (shootVelocity * 2).RotatedByRandom(0.5f) * Main.rand.NextFloat(0.8f, 1.2f),
        ProjectileType<VitriolicViperFang>(), Projectile.damage / 10, ...);
```
✅ **33 是"蝰蛇有 33 颗牙"的梗**（源码注释直说了）。
- 每颗 `damage / 10` → 全中 = 330% 总伤
- **散布 `RotatedByRandom(0.5f)` = ±28.6°**，速度 `×2 × rand(0.8, 1.2)`
- 是"短程"因为 `VitriolicViperFang` 本身寿命短，不是因为速度慢

满蓄枪口 ✅：
- 1 个 `CustomPulse(GunTip, Zero, bColor, "HighResFoggyCircleHardEdge", Vector2.One, rand(-10,10), 0f, 0.05f, 14)`
- 17 个 `DustID.FireworksRGB`（速度 `rand(5,25)`，scale `rand(0.45,0.75)`）
- **19×2 = 38 个 `LineParticle`**：
  ```csharp
  for (int i = 0; i <= 18; i++) {
      // 内层：RotatedByRandom(0.45f) * rand(0.5, 0.7)   scale rand(0.3, 0.8)   — 散而慢
      // 外层：RotatedByRandom(0.2f)  * rand(0.9, 1.6)   scale rand(0.4, 1.0)   — 聚而快
      颜色 50/50 在 Chartreuse 与 Green 之间
      寿命均为 40
  }
  ```
  **两层散布/速度完全相反的线粒子**（宽慢 + 窄快）叠在一起，形成"核心射流 + 外围飞溅"的双层锥。这比单层 38 个线粒子层次丰富得多。

### 蓄力过程的视觉 ✅
```csharp
vortexRotation += 0.4f * chargePower;      // 转速随蓄力加快

if (CurrentChargingFrames >= 10) {         // 前 10 帧完全没有视觉反馈（防误触）
    if (FirstCharge) {   // 第二段：双点公转
        for (int i = 0; i < 2; i++) {
            Vector2 dustPos = GunTipPosition
                + (i * MathHelper.Pi + vortexRotation * 0.35f + MathHelper.PiOver2).ToRotationVector2()
                  * 20f * chargePower * overchargePower;
            dust = SulphurousSeaAcid @ dustPos, 速度 (...)*4, noGravity, scale rand(0.85, 0.9);
        }
    } else {             // 第一段：无序喷散
        dust = SulphurousSeaAcid @ GunTipPosition,
               速度 new Vector2(12,12).RotatedByRandom(100) * rand(0.2,1) * chargePower * overchargePower,
               scale rand(0.6, 0.7);
    }
}
```
**两段的视觉语言完全不同**：
- 第一段（0~30 帧）：**无序的酸尘四散** → "在积蓄"
- 第二段（30~60 帧）：**两个尘点绕枪口 20 像素半径对称公转**（`i * π` 即相隔 180°），转速 `vortexRotation * 0.35` → "已经成型，在旋转加速"

这是极其清晰的两段式提示，玩家一眼就知道自己在哪个阶段。

**两个里程碑的一次性反馈** ✅：
| 时刻 | 音效 | 粒子 |
|---|---|---|
| 第一段满（`CurrentChargingFrames == 30 && CurrentOverchargeFrames == 0`） | `NuclearTerrorHit` **Pitch -0.2** | 18 个 `FireworksRGB`，位置 `GunTip + dustVel`，速度 `dustVel * 0.7f`（`dustVel = Vector2.One.RotatedByRandom(100) * rand(1,5)`），**`noGravity = true`** |
| 第二段满（`CurrentOverchargeFrames == 30`） | `NuclearTerrorHit` **Pitch +0.2** | 12 个 `FireworksRGB`，速度 `rand(2, 5.5)`，scale `rand(0.75,1.1)`，**`noGravity = false`（会掉落）** |

**同一个音效、音高差 0.4，就区分了两个里程碑。** 且粒子的 `noGravity` 相反：第一段的悬浮（能量成型），第二段的掉落（过载溢出）。

## 4. Ion Blaster / 离子冲击波 / 魔法（与 Apoctosis Array 同架构）

### 蓄力 = 回魔 ✅
右键不是"蓄力"，而是**主动回魔**，`manaPower` 只是回魔过程的副产品：

```csharp

Owner.statMana += (int)(Owner.statManaMax2 * 0.025f);   // ✅ 官方"隔帧回 2.5% 魔力"
// 源码注释：// 80 frames to reach max mana

if (manaPower > 1) manaPower = 1;
```
- **回魔：每 2 帧 +2.5% → 满魔需 80 帧（1.33 秒）** ✅
- **蓄力值：每 2 帧 +0.0275 → 满值需约 72 帧（1.2 秒）**

满蓄判定：
```csharp

    for (int i = 0; i < 2; i++)
        SoundEngine.PlaySound(fullCharge with { Volume = .6f, Pitch = -0.7f + i * 1.5f, MaxInstances = 2 });
    fullyCharged = true;
}
```
⚠️ `isAtMaxMana` 的定义是 `(statMana / statManaMax2) >= 1`，即 **100% 魔力**。官方 wiki 写的是"恢复 90% 最大魔力"——**源码是 100%**。这个差异复刻时需要注意（可能是 tooltip 取整或版本差）。

满蓄音效很有巧思：**同一个 `DudFire` 播两次，音高 -0.7 和 +0.8**（`-0.7 + i * 1.5`）。一低一高同时响，形成一个"叮"的和声，比单音清楚得多。

### 满蓄爆发：24 发 ✅

```csharp
                  * (1 - Math.Abs(variance))
                  * (i % 2 == 0 ? 0.7f : 1)
                  * Main.rand.NextFloat(5f, 5.5f);

                             Projectile.knockBack * 2, ..., 0, 0, 5);
```

- `(i % 2 == 0 ? 0.7f : 1)` **奇偶交替 0.7/1.0 速度** → 24 发自动分成前后两批，形成纵深（与 Blissful Bombardier 的 40 dust 双层环同理）

## 5. Volterion / 雷霆意志 / 魔法

### 实体拓扑 ✅
```
Volterion (物品) └─ VolterionHoldout └─ VolterionShot（高压栓）
                                          └─ VolterionOrb × 5   ✅ 官方"裂 5 电球"
```

### 这是第 2 篇第一把用 **L3 图元带**的武器 ⚠️

```csharp
public override bool PreDraw(ref Color lightColor)
{
    GameShaders.Misc["CalamityMod:HeavenlyGaleLightningArc"].UseImage1("Images/Misc/Perlin");
    GameShaders.Misc["CalamityMod:HeavenlyGaleLightningArc"].Apply();
    PrimitiveRenderer.RenderTrail(TrailPos,
        new(TrailWidthFunction, TrailColorFunction, smoothen: false,
            shader: GameShaders.Misc["CalamityMod:HeavenlyGaleLightningArc"]),
```

**三个关键点**：
1. **`smoothen: false`** —— 关闭样条插值。闪电必须是**折线**，平滑化会毁掉它。这与绝大多数拖尾（默认 `smoothen: true`）相反。
2. **`UseImage1("Images/Misc/Perlin")`** —— 用柏林噪声贴图驱动闪电的抖动。这就是 `HeavenlyGaleLightningArc` 着色器产生"电弧扭动"的来源，**不是靠代码逐帧改顶点位置**。
3. 颜色函数：
   ```csharp
   internal Color TrailColorFunction(float completionRatio, Vector2 vertexPos) =>
       OrbType > 0f ? VolterionOrb.GetColor(OrbType - 1f)
                    : Color.Lerp(new Color(51, 197, 255), new Color(143, 51, 255),
                                 0.5f + 0.5f * MathF.Sin(Main.GlobalTimeWrappedHourly * 20f)) * Projectile.Opacity;
   ```
   **青（51,197,255）↔ 紫（143,51,255）以 20 倍全局时间做 sin 插值** → 约 3.2 Hz 的快速色相跳动，制造电流不稳定感。

### 五电球的分色 ✅
```csharp
for (int i = 0; i < 5; i++)
    Projectile orb = NewProjectileDirect(..., ProjectileType<VolterionOrb>(), ..., i);   // ai[0] = i
...
Color color = OrbType > 0f ? VolterionOrb.GetColor(OrbType - 1f)
                           : (Main.rand.NextBool() ? Color.Cyan : Color.Orchid);
```
**每个球带一个编号 `i`，由 `VolterionOrb.GetColor(i)` 决定颜色。** 5 个球不是同色 —— 这是官方"球半径、雷束宽/次数未公开"之外的一个额外发现：**它们在视觉上是可区分的个体**。

### 粒子构成 ✅
- **`BoltParticle`**（闪电粒子，非图元带）
  - 飞行中：`new BoltParticle(Center, velocity.RotatedByRandom(MathHelper.ToRadians(36f)), false, 10, 0.3f, TrailColorFunction(0f, Vector2.Zero), Vector2.One, true)` —— **±36° 的随机分叉**，生命仅 10 帧

- 7 个 `DustID.FireworksRGB`，颜色 50/50 `Cyan` / `Orchid`
- Holdout 开火：8 个 `PointParticle(offsetPos, randVelocity, false, 15, scale, new Color(51, 197, 255))` —— **`PointParticle` 是最小单位光点**，用它做枪口星火极其廉价

### 释放法评点
`BoltParticle` 的 **±36° 分叉**是闪电感的核心。36° 不是随便取的：太小（<15°）看起来像抖动的直线，太大（>60°）看起来像爆炸。**36° 恰好是"分叉但仍有主方向"的临界带。**

配合 `smoothen: false` 的主干图元带，形成"锐利主干 + 随机分叉"的经典闪电结构。

> **可复刻要点**：闪电 = `smoothen: false` 的图元带 + Perlin 噪声着色器 + ±36° 的短命分叉粒子。三件缺一不可。只做图元带会显得呆，只做粒子会没有主干。

## 6. Seething Discharge / 沸腾之火 / 魔法

**全部逻辑都在物品的 `Shoot` 里，没有 holdout。这是最简洁的一把，正因如此它的几何非常值得学。**

### 5 炎爆的"弧形"是生成位置，不是发射方向 ⚠️
```csharp
float diameter = 50f;
Vector2 projVelocity = velocity.SafeNormalize(Vector2.UnitY) * diameter;   // 长度 50 的方向向量

int totalProjectiles = 5;
float offsetAngle = MathHelper.Pi * 0.2f;                                   // 36°

for (int j = 0; j < totalProjectiles; j++)
{
    float radians = j - (totalProjectiles - 1f) / 2f;                       // j=0..4 → -2,-1,0,1,2
    Vector2 offset = projVelocity.RotatedBy(offsetAngle * radians);         // -72°,-36°,0°,+36°,+72°
    Projectile.NewProjectile(source, player.Center + offset, velocity, ...);
    //                               ↑ 位置在弧上          ↑ 速度全部相同！
}
```

✅ **这是本篇最容易被误解的一处。** 官方说"固定弧形 5 炎爆"，很容易理解成"扇形散射"。**实际上五发的速度向量完全一样（都朝光标），只有生成位置排成一个半径 50 的弧。**

结果：五发**平行飞行**，保持一字排开的阵列，像一堵墙推过去，而不是散开成扇。

- 弧的张角：`±72°`，总共 144°
- 弧半径：**50 像素**
- 弧的朝向随光标旋转（因为 `projVelocity` 是归一化后的瞄准方向）

**如果照抄成扇形散射，武器手感会完全改变**——散射打不中远处小目标，平行阵列则是一堵可靠的墙。

### 逢三触发的 8 环镖 ✅
```csharp
DartTimer++;
if (DartTimer == 3)
{
    DartTimer = 0;
    totalProjectiles = 8;
    Vector2 initialOffset = Vector2.UnitX.RotatedBy(Main.rand.NextFloat(0f, MathHelper.PiOver4));
    for (int k = 0; k < 8; k++)
    {
        velocity = initialOffset.RotatedBy(MathHelper.TwoPi * (k / 8f)) * Item.shootSpeed;   // shootSpeed = 10
        Projectile.NewProjectile(source, player.Center, velocity, type, damage, 0f, player.whoAmI, 0f, 1f);
    }
}
```
✅ **8 枚，完美均分 360°，速度 10，从玩家中心射出。**
- `initialOffset` 随机旋转 **0~45°**（`PiOver4`）→ **每次环的朝向不同**，避免重复感。因为 8 等分的间隔正好是 45°，所以 0~45° 的随机覆盖了完整的相位空间，**不多不少**。这个细节很讲究。
- `ai[1] = 1f` 是"环镖"标记，`SeethingDischargeBrimstoneBarrage` 用它切换到"短延迟后追踪"的分支 ✅
- **击退为 0** —— 环镖不推敌人，避免把敌人推出 5 炎爆的路径

### 释放法评点
`useTime = 60`（1 秒一发），所以"逢三"= **每 3 秒一次**环镖。节拍非常清晰：
```
第 1 秒：5 炎爆
第 2 秒：5 炎爆
第 3 秒：5 炎爆 + 8 环镖   ← 爆点
```
> **可复刻要点**：`Main.rand.NextFloat(0f, TwoPi / n)` 这种"随机相位恰好等于一个等分间隔"的写法，是让规整阵列不显呆板的标准做法。随机范围超过间隔是浪费，不足则会有可见的偏好方向。

## 7. Sanguine Flare / 猩红烈焰 / 魔法

### 蓄力倍率与血球数的联动 ✅
```csharp
Projectile.damage = (int)(Projectile.damage * dmgMult);          // dmgMult ∈ [1, 5] → 100%~500% ✅

// 命中时：
float orbCount = MathHelper.Lerp(0, 20, (dmgMult - 1) / 4f);     // ✅ 0 → 20 球
for (...)
    Projectile.NewProjectile(..., Projectile.velocity.RotatedByRandom(1) * Main.rand.NextFloat(0.75f, 1.25f),

```

**官方三个数字全部源码确证：**
- 最高 **500%** ← `dmgMult` 上限 5
- 最多 **20** 血球 ← `Lerp(0, 20, (dmgMult-1)/4)`，`dmgMult = 5` 时取 20
- 每球减药水病 **0.3 秒** ← `BloodstoneOrbValue = 18` 帧

⚠️ **注意 `(dmgMult - 1) / 4f` 是线性的**：`dmgMult = 1`（无蓄力）时球数为 **0**。不蓄力就完全没有血球——这是一个很硬的设计，逼玩家蓄力。

### 视觉：血腥模式的双套配色
和 Claret Cannon 一样走 `!ChildSafety.Disabled ? A : B`，但这把用了**三组**不同的配对：

## 8~10. 「矢」三兄弟：Frost Bolt / Flare Bolt / Frigidflash Bolt

### 共享骨架：施法定型阶段 ✅

✅ **弹体在使用动画的前一半（`itemAnimationMax * 0.5f`）里，悬停在玩家身前 48 像素处、从 scale 0 长到满**，然后才射出。

### Frost Bolt / 冰矢 ✅

**发射瞬间**：`CryogenHit`（Pitch 0.3）+ **8 个 `LightDust`**（`Vector2.One.RotatedByRandom(100) * rand(0.5, 1.5)`，`noGravity = false`，染 `DeepSkyBlue`，`noLightEmittence = true`）

**飞行拖尾**（两层）：
```csharp

                new Vector2(1, 1f), true, false, shrinkSpeed: 0.8f);
```

### Primordial Ancient 的"先分后聚"是怎么做的 ✅

官方说"5 个附魔沙爆延迟汇于光标并爆"。实现方式很巧妙——**不是让它们追踪同一个点，而是给每股一个"曲率权重"**：

```csharp
// 物品的 Shoot：
for (int i = -2; i <= 2; i++)
{
    Vector2 vel = velocity.RotatedBy(0.1f * i) * MathHelper.Lerp(3 - Math.Abs(i), 1, 0.7f);
    Projectile dust = NewProjectileDirect(source, position, vel, type, damage, knockback, player.whoAmI,
                                          0f, i == 0 ? 1 : 0, MaxMana ? 1f : 0f);
    dust.localAI[0] = i * 0.45f;          // ← 曲率权重：-0.9, -0.45, 0, 0.45, 0.9
}

// 弹幕的 AI：
curve = MathHelper.Lerp(curve, 0f, 0.035f);            // 从 0.02 衰减到 0
Projectile.velocity = Projectile.velocity.RotatedBy(curve * Projectile.localAI[0]);
```

- **`localAI[0] = i * 0.45f`**：外侧两股权重 ±0.9、内侧 ±0.45、正中 0
- **每股按自己的权重反向弯曲** → 偏得越远的转得越急，自然向中轴收拢
- **`curve` 从 0.02 指数衰减到 0**（`lerp` 系数 0.035，约 65 帧衰减到 5%）→ **弯曲只发生在飞行早期**，之后各自笔直前进

结果就是"五股沙流先张开、再向内并拢、然后平行推进"——**没有任何一行代码在计算"光标位置"**。这比追踪实现优雅得多，也不会出现追踪特有的"急转弯"丑态。

初速 `Lerp(3 - |i|, 1, 0.7f)` 展开：
- `i = 0` → `Lerp(3, 1, 0.7) = 1.6`
- `i = ±1` → `Lerp(2, 1, 0.7) = 1.3`
- `i = ±2` → `Lerp(1, 1, 0.7) = 1.0`

**中间最快、两侧最慢** → 汇聚时正中那股先到，两侧包夹。这个速度差与曲率差配合，才形成"箭头"形状而不是"一条线"。

自转也绑权重：
```csharp
Projectile.rotation += Main.rand.NextFloat(0.1f * Utils.GetLerpValue(-100, 360, time))
                       * (float)Projectile.direction * Projectile.localAI[0];
```
**正中那股（`localAI[0] = 0`）完全不自转**，外侧转得最快。视觉上形成"稳定核心 + 翻滚外缘"。

### Primordial Earth 的"两道交汇" ✅

### 释放法评点

三把武器的"档次感"完全靠**数量 + 几何复杂度**堆出来，粒子构成几乎一模一样：

```
Death Valley Duster : 1 股，直线            → "一团沙"
Primordial Earth    : 2 股，对向弯曲交汇     → "两道沙流绞在一起"
Primordial Ancient  : 5 股，权重曲率收拢     → "沙暴箭头"
```

> **可复刻要点**：**要做"多股汇聚"，不要用追踪，用"按索引分配的曲率权重 + 衰减的曲率系数"。**
> `localAI[0] = i * k` 配合 `curve → 0` 的指数衰减，能得到平滑、可预测、且形状稳定的收拢轨迹。追踪实现会因为目标点抖动而产生难看的急转。

| 初速 | `rand(6f, 9f)` | **`2.75f`**（慢 2~3 倍） |
| 寿命 | 默认 | **`× 3`** |
| `ai[2]` | `0f` | `1f` |
| 伤害 | `damage × 0.33f` | 同 |

**速度慢 + 寿命长 = 留在原地能被吸收**。这个设计非常干净：不需要额外的"停留"逻辑，靠初速和寿命两个数就区分了两种行为。

发射方向 `-Vector2.UnitY.RotatedByRandom(MathHelper.Pi)` = **以正上方为基准的全向随机**（±180°）。

### 爆炸视觉 ✅
```csharp
SoundEngine.PlaySound(SoundID.Item105, Projectile.Center);

// 25 个等离子光球
for (int i = 0; i < 25; i++) {
    Vector2 plasmaVelocity = Vector2.One.RotatedByRandom(MathHelper.TwoPi) * Main.rand.NextFloat(6f, 11f);
    Color   plasmaColor    = Color.Lerp(FindColorForSoul((int)Projectile.ai[0]), Color.White, Main.rand.NextFloat());
    new SquishyLightParticle(Projectile.Center, plasmaVelocity, rand(0.8f, 1.4f), plasmaColor, rand(30, 45));
}

// 15 个可染色尘
for (int i = 0; i < 15; i++) {
    Dust dust = DustID.TintableDustLighted @ Center, NextVector2Circular(1,1) * 6f,
                scale rand(1.8f, 2.4f), color Lerp(FindColorForSoul(...), White, rand);
    dust.noGravity = true;  dust.noLight = false;  dust.noLightEmittence = false;
}
```
**颜色全部由灵魂类型决定**（`FindColorForSoul`），源码里的六色表：
```
(123, 29, 220)   紫
(106, 240, 250)  青
(4, 51, 222)     蓝
(79, 255, 124)   绿
(255, 96, 20)    橙
```
每个粒子再 `Lerp(灵魂色, White, rand)` 随机向白偏 → **同一次爆炸里有从纯色到纯白的完整梯度**，而不是 25 个同色球。这是让"一团彩色爆炸"不显廉价的关键。

⚠️ `dust.noLight = false` 且 `noLightEmittence = false` —— **这 15 个尘会真实发光**，与 25 个纯视觉的 `SquishyLightParticle` 分工明确：粒子做形状，尘做照明。

**弹体本身的 scale 是一条分段曲线**：
```csharp
if (Projectile.timeLeft >= 285)                     Projectile.scale += 0.125f;                    // 前 15 帧：膨胀
else if (timeLeft <= 285 && timeLeft >= 45)         Projectile.scale = Lerp(minScale, maxScale,
                                                        CalamityUtils.SineBumpEasing(localAI[0] / 75f, 1));  // 中段：正弦鼓包脉动
else                                                Projectile.scale = Remap(timeLeft, 45, 0, localAI[1], 0.35f);  // 末 45 帧：收缩
```
`SineBumpEasing` 让球在飞行中段**周期性地鼓胀**（周期 75 帧），像不稳定的等离子。`explodeRange = 250f`。

## 19. Apoctosis Array / 凋亡射线 / 魔法（与 Ion Blaster 同架构）

**代码与 Ion Blaster 逐行对应**，两把武器共用同一份 holdout 模板。以下只列**差异项** ✅：

| | Ion Blaster | Apoctosis Array |
|---|---|---|
| 回魔速率 | 每 2 帧 +2.5%（80 帧满） | **完全相同** |
| `manaPower` 增速 | 每 2 帧 +0.0275（72 帧满） | **完全相同** |
| 满蓄判定 | `isAtMaxMana && manaPower >= 0.25f` | **完全相同** |
| 满蓄音效 | `DudFire` ×2，Pitch -0.7 / +0.8 | **完全相同** |
| **终结形态** | **24 发散射** | **1 支大型穿透箭** |
| 伤害公式 | `manaPower >= 1 ? 1.9f : 1.6f` | `Math.Max((manaPower * 60) * (manaPower >= 1 ? 1.5f : 1f), 1)` |
| 屏震 | `6f * manaPower` | **`12f * manaPower`**（双倍） |
| 弹速倍率 | — | `(manaPower + 0.4f) * (manaPower >= 1 ? 3f : 2f)` → 满蓄 **4.2×** |
| 击退 | `knockBack * 2` | **`knockBack * 4`** |
| 音效层数 | 1~2 | `(manaPower >= 1 ? 2 : 1)` 层叠播 |
| 失败反馈 | 10 个 dust | 10 个 dust，`scale = rand(0.95,1.35) * (manaPower + 0.3f)` |

✅ **`(manaPower >= 1 ? 1.5f : 1f)` 就是官方说的"恢复 90% 最大魔力时箭伤 1.5×"**——满蓄时整体伤害额外 ×1.5。同样地，源码的门槛是 **100%** 魔力而非 wiki 写的 90%。

`RecoilResolveSpeed => shootingTimer >= 0 ? 0.3f : 0.05f` —— **射击后回弹快（0.3），蓄力期回弹极慢（0.05）**。蓄力时枪会一直保持后缩姿态，是个持续的视觉提示。

`shootingTimer = -40` 用负值标记"蓄力中"状态，复用同一个变量做两件事。

> **可复刻要点**：Ion Blaster 与 Apoctosis Array 是"**同架构、异终结**"的教科书。回魔机制、蓄力曲线、满蓄音效全部共享，只有最后那一下不同（24 发散射 vs 1 支重箭）。**做系列武器时，共享的应该是"过程"，差异化的应该是"结算"。**

## 20. Alpha Draconis / 天龙座阿尔法 / 魔法

### 天降星的生成几何 ✅
```csharp
var mousePos = player.Calamity().mouseWorld;
for (var i = 0; i < 3; i++)
    Projectile.NewProjectile(source,
        new Vector2(mousePos.X, player.Center.Y)
            + new Vector2(Main.rand.Next(500, 1300) * -player.direction, Main.rand.Next(-800, -600)),
        Vector2.UnitX * player.direction * velocity.Length(),
        type, damage, knockback, player.whoAmI, mousePos.X, mousePos.Y);
```
✅ **每次 3 颗星**（官方"星数未公开"）。
- **生成点**：X 取光标横坐标，再沿玩家**背后**方向偏移 `rand(500, 1300)` 像素；Y 取玩家高度再上移 `rand(600, 800)` 像素
- **初速是纯水平的**（`Vector2.UnitX * player.direction * 8f`）—— 星星从玩家身后的高空**横着飞过来**，而不是垂直落下
- `ai[0]`/`ai[1]` 传光标坐标，星星在飞行中朝这个点俯冲

**这个"从背后高空横向切入"的生成方式，是天降类武器最容易做错的地方。** 直接在光标正上方生成会让星星"凭空出现"；从背后远处切入则给了玩家一个可追踪的运动轨迹。500~1300 的随机跨度保证三颗星不会同步。

### 右键星座：召唤 / 撤除是同一个键 ✅
```csharp
if (player.altFunctionUse == 2)
{
    if (player.ownedProjectileCounts[ProjectileType<DracoConstellation>()] > 0)
    {
        var p = Main.projectile.First(x => x.type == ProjectileType<DracoConstellation>() && x.active && x.owner == player.whoAmI);
        p.timeLeft = (int)MathHelper.Min(p.timeLeft, 60);         // ← 撤除：把寿命压到 60 帧
    }
    else
        Projectile.NewProjectile(source, player.Center + new Vector2(-125, -100), -Vector2.Zero,
                                 ProjectileType<DracoConstellation>(), (int)(damage * 4f), knockback, player.whoAmI);
    return false;
}
```
✅ **`damage * 4f` = 400%** —— 精确对应官方"右键召天龙座冲敌（400%）"。
- **撤除不是立即消失，而是把 `timeLeft` 压到 60 帧**（1 秒）→ 星座有一个完整的退场动画，不会突兀地消失。`MathHelper.Min` 保证如果本来就快没了不会反而延长。
- 生成偏移 `(-125, -100)` —— 固定出现在玩家**左上方**

## 第 2 篇小结：魔法系的四条通用法则

1. **"施法定型"是统一开场**：弹体先悬停在玩家身前 48 像素、scale 从 0 长满，再射出。三把「矢」逐字共用这段代码。它把"攻速"翻译成了"凝聚快慢"。

2. **状态机比参数更重要**。魔法武器的重做几乎都是"给弹体加一个状态"：
   - Anahita：绕身 → 淡出瞬移 → 光标收束
   - Phantasmal Fury：柔性绕身 → 齐飞索敌
   - Burning Sea：成长 → 牵引 → 红烟 → 烧尽
   - Flare Bolt：飞行 → 刹停 → 涡流

3. **"环绕"有两种实现，选错手感全变**：
   - **硬定位**（`Center = 圆心 + 半径.RotatedBy(角度)`）→ 仪式感、绝对稳定（Anahita）
   - **柔性追逐**（`velocity += 朝目标点的加速度`，带速度上限）→ 生命感、松散漩涡（Phantasmal Fury）

4. **资源状态要多通道冗余编码**：Ion Blaster 用音高（连续）+ 弹数（断崖）+ 伤害（断崖）+ 后坐（连续）四路表达同一个 `manaPower`。

**并且——魔法系有两把武器的主特效根本不是视觉的**：Anahita's Arpeggio 的六个竖琴音（`HarpLV1~6`）、Vitriolic Viper 的两级里程碑音高。复刻时若只抄粒子不抄音效，这两把武器会彻底失魂。
