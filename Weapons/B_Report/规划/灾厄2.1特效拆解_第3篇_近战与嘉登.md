### 1.3 时间轴：三段式

```csharp
public int   CooldownStartFrame => swingTime + StartupTime;
public bool  inStartup  => timer < StartupTime;
public bool  inCooldown => timer > CooldownStartFrame;
public bool  inSwing    => !(inStartup || inCooldown);

public float StartupCompletion => timer / (float)StartupTime;
public float SwingCompletion   => swingTimer / (float)swingTime;
public float CooldownCompletion=> CooldownTimer / (float)CooldownTime;

public override bool? CanDamage() => inSwing;      // ← 只有挥砍段有伤害
```

**`ExistsTime = swingTime + StartupTime + CooldownTime`**，`Projectile.timeLeft = ExistsTime * 2`。

⚠️ **起手期和收招期完全无伤害。** 这是 2.1 近战手感的根本改变——剑不再是"举起来就有判定"，而是有明确的前摇后摇。给了敌人反应窗口，也给了特效表现窗口。

### 1.4 攻速与尺寸如何介入（`FakeOnSpawn`）✅


✅ **攻速加成被硬钳在 3 倍**（`if (speed > 3f) speed = 3f`）。这是官方从未公布的平衡上限。
✅ **三段时间等比缩放** —— 攻速快时前摇后摇一起变短，动作节奏不会失真。

### 1.5 挥砍运动学：一行公式 ⚠️

```csharp
public virtual float SwingFunction()
{
    return MathHelper.ToRadians(MathHelper.SmoothStep(-swingWidth / 2, swingWidth / 2, swingTimer / (float)swingTime));
}

// AI 里：
var angle2 = SwingFunction();
Projectile.Center   = armCenter - (angle * OffsetDistance * (1 + (Projectile.scale - 1) * 0.75f))
                                  .RotatedBy(Projectile.spriteDirection * angle2);
Projectile.rotation = angle.RotatedBy(Projectile.spriteDirection * angle2).ToRotation() + adust;
```

**`MathHelper.SmoothStep` 是整个近战手感的心脏。** 它是 3 次 Hermite 插值（`3t² - 2t³`），特征是**两端导数为 0**——即挥砍**起步慢、中段最快、收尾慢**。

> 如果换成线性 `MathHelper.Lerp`，剑会以匀速扫过 180°，看起来像雨刷器。**`SmoothStep` 那个"中段加速"就是"力量感"的全部来源。**

`adust`（角度修正）：`spriteDirection == -1` 时是 `-45°`，否则 `225°` —— 用于把剑的贴图朝向对齐到挥砍切线。

`armCenter = player.MountedCenter - new Vector2(5 * player.direction, 2)` —— 旋转中心不是玩家正中，而是**肩部**（水平偏 5、垂直偏 2）。

尺寸对距离的影响：`OffsetDistance * (1 + (scale - 1) * 0.75f)` —— **剑变大 1 倍时，握持距离只增加 0.75 倍**。次线性，避免大剑离手太远显得脱节。

### 1.6 左右交替 ✅
```csharp
if (AlternateSwings && player.GetModPlayer<BaseSwordHoldoutPlayer>().swingNum % 2 == 1)
    Projectile.spriteDirection *= -1;
if (AlternateSwings)
    player.GetModPlayer<BaseSwordHoldoutPlayer>().swingNum++;
```
**`swingNum` 存在 `ModPlayer` 上而非弹幕上** —— 因为弹幕每次挥砍都会重建，计数必须跨实例保留。这就是"自定义快速左右挥"的实现（Basher、Grand Guardian、Majestic Guard、Hellkite 等全部靠它）。

⚠️ 源码里有一处冗余：
```csharp
var angle2 = (AlternateSwings && modplayer.swingNum % 2 == 1 ? SwingFunction() : SwingFunction());
```
**三元表达式两边完全相同** —— 交替实际是靠 `spriteDirection *= -1` 实现的，这行是残留代码。

### 1.7 拖尾：图元带 + `ExobladeSlash` 着色器 ✅

```csharp
GameShaders.Misc["CalamityMod:ExobladeSlash"].Shader.Parameters["flipped"]
    .SetValue(Projectile.spriteDirection == -1 ? false : true);
GameShaders.Misc["CalamityMod:ExobladeSlash"].Apply();

var positionsToUse = Projectile.oldPos.Take((int)MathHelper.Min(trailLength, swingTimer)).ToArray();
for (var i = 0; i < positionsToUse.Length; i++)
{
    if (i >= timer) break;
    positionsToUse[i] += (Projectile.oldRot[i] - MathHelper.PiOver4 * (Projectile.spriteDirection == -1 ? 3 : 1))
                         .ToRotationVector2() * this.trailOffset * oldScale[i];
}
PrimitiveRenderer.RenderTrail(positionsToUse,
    new(trailWidth, trailColor, (_, _) => trailOffset, shader: GameShaders.Misc["CalamityMod:ExobladeSlash"]), 25);
```

**四个要点**：
1. **拖尾采样点不是剑的中心，而是剑尖**——每个历史位置沿它当时的旋转角外推 `trailOffset * oldScale[i]`。**`oldScale[i]` 单独记了一份历史缩放**，所以尺寸变化的剑（蓄力变大）拖尾也会跟着变宽。
2. `Take(Min(trailLength, swingTimer))` —— **挥砍刚开始时拖尾长度也从 0 开始增长**，不会一上来就是一条完整的弧。
3. 默认宽度函数是 `MathHelper.Lerp(30, 0, completion)` —— **根部 30 像素、尖端收 0**，标准的刀光形状。
4. `ProjectileID.Sets.TrailCacheLength = 100`、`TrailingMode = 2`。

`flipped` shader 参数由 `spriteDirection` 驱动 —— 左右挥时刀光的渐变方向会翻转，否则反手挥砍的刀光会"倒着亮"。

### 1.8 线段碰撞：解决近身盲区 ✅
```csharp
public override bool? Colliding(Rectangle projHitbox, Rectangle targetHitbox)
{
    if (lineCollisionLength > 0)
    {
        var armcenter = player.MountedCenter - new Vector2(5 * player.direction, 2);
        var swordDir = armcenter.DirectionTo(Projectile.Center);
        var collisionline = new Vector2(lineCollisionLength / 2f, 0).RotatedBy(swordDir.ToRotation()) * Projectile.scale;
        bool c = Collision.CheckAABBvLineCollision(targetHitbox.Location.ToVector2(), targetHitbox.Size(),
                                                   Projectile.Center, Projectile.Center + collisionline);
        if (c && !float.IsNaN(collisionline.X) && !float.IsNaN(collisionline.Y))
            return true;
    }
    return base.Colliding(projHitbox, targetHitbox);
}
```
**矩形判定（剑身）+ 沿剑方向的线段判定（补全剑刃）双管齐下。** 只有矩形时，贴脸的敌人会从剑与玩家之间的空隙漏过去。这就是注释说的 "This helps to prevent blindspots"。

`ModifyDamageHitbox` 里判定框按 `Projectile.scale` 等比缩放。

击退方向被强制覆写：
```csharp
modifiers.HitDirectionOverride = (player.DirectionTo(target.Center).X >= 0 ? 1 : -1);
```
→ **永远把敌人推离玩家**，不受剑当前朝向影响。

### 1.9 `shootCheck()`：挥砍中均匀发射子实体 ⚠️

这是**近战武器发射弹幕的官方工具**，几乎所有"挥砍时射出 N 个东西"的武器都用它：

```csharp
public void shootCheck(int type = 0, float velocity = 1, float damagemod = 1, int amount = 0, int negate = 0, int ai0 = 0)
{
    if (negate == 0) negate = Projectile.spriteDirection;

    if (amount == 0)   // amount 为 0 → 立即强制发射一发
    {
        Projectile.NewProjectile(..., (Projectile.rotation + negate * MathHelper.ToRadians(45 - negate * 90)).ToRotationVector2() * velocity,
                                 type, (int)(Projectile.damage * damagemod), ...);
        return;
    }

    amount += 1;
    if (swingTimer % (swingTime / amount) == 0 && swingTimer > 0 && swingTimer < swingTime - swingTime / amount / 2)
        Projectile.NewProjectile(...);      // ← 沿挥砍弧均匀撒 N 发
}
```

**关键在发射方向**：`Projectile.rotation + negate * (45° - negate * 90°)`
- `negate = 1`（正手）→ `rotation + 1 * (45 - 90) = rotation - 45°`
- `negate = -1`（反手）→ `rotation - 1 * (45 + 90) = rotation - 135°`

即**始终沿剑刃的法线方向射出**，而不是沿剑的朝向。所以子弹幕看起来是"被刀锋甩出去的"，符合物理直觉。

**均匀撒布的时机判定**：`swingTimer % (swingTime / amount) == 0` 把挥砍过程等分成 `amount + 1` 段，在每个分界点发射。末尾的 `swingTimer < swingTime - swingTime / amount / 2` 排除掉收尾半段，**避免最后一发挤在挥砍结束的瞬间**。

> ⚠️ **注意：因为发射点是 `swingTimer` 的等分，而 `swingTimer` 走的是 `SmoothStep` 的角度曲线，所以子弹幕在角度上并不均匀——中段密、两端疏。** 这恰好符合"挥砍最快处甩出最多"的直觉。复刻时若改成按角度均分，反而会失去这种加速感。

## 第三部分：誓约剑三兄弟（Oathblade 家族）

Devil's Devastation / Exalted Oathblade / Forbidden Oathblade。
**它们不走 `BaseSwordHoldoutProjectile`，而是走 `BaseCustomUseStyleProjectile`** —— 因为需要"举剑姿态 + 蓄势 + 巨大斩击"这套更复杂的动画，而不是简单的弧线挥砍。

### 3.1 共享资源：`demonSwordImpales`（插刃计数）✅

三把剑的插刃上限**全部由 NPC 身上的同一个计数器 `target.Calamity().demonSwordImpales` 控制**：

```csharp
// ExaltedOathbladeThrownBlade.cs:250
```

⚠️ **这是一个 per-NPC 的共享计数器，不是 per-weapon。** 意味着如果两个玩家分别用禁忌之刃和破灭魔王剑插同一个敌人，计数是共用的。官方日志完全没提这一点。

三把剑的 `ThrownBlade` 里都有 `Projectile.localAI[0] == 5` 的判定（脱落条件之一），且都以
```csharp

```
作为"插着的剑该消失了"的统一条件。

### 3.3 斩击的运动学：270° 的 ExpInOut 大回旋 ✅

**待机举剑**（`RotationOffset` 的目标值）：
```csharp
RotationOffset = MathHelper.Lerp(RotationOffset,
    MathHelper.ToRadians(120f * Projectile.ai[1] * Owner.direction
        * (1 + Utils.GetLerpValue(useAnim * 0.7f, useAnim, Animation, true) * 0.35f)),
    0.2f);
```
基础 120°，**在动画最后 30%（`useAnim * 0.7f` 之后）额外拉大 35% → 162°** —— 也就是斩击前剑会**再往后收一点**，蓄势。

**斩击本体**：
```csharp
float time    = AnimationProgress - (useAnim / 3);
float timeMax = useAnim - (useAnim / 3);

RotationOffset = MathHelper.Lerp(RotationOffset,
    MathHelper.ToRadians(MathHelper.Lerp(
        150f * Projectile.ai[1] * Owner.direction,      // 起点 +150°
       -120f * Projectile.ai[1] * Owner.direction,      // 终点 -120°
        CalamityUtils.ExpInOutEasing(time / timeMax * 0.9f, 1))),
    ...);
```
✅ **总扫过 150° − (−120°) = 270°**，用 `ExpInOutEasing`（指数进出缓动）。

**`ExpInOut` 与基类的 `SmoothStep` 的区别**：`SmoothStep` 是 3 次多项式，中段加速温和；`ExpInOut` 是指数曲线，**中段的爆发要剧烈得多，两端几乎静止**。这正是"杀戮斩"应有的手感——举着不动、突然一闪、又停住。

`* 0.9f` 让缓动只走到 90% 就结束 —— **斩击在最后 10% 提前定格**，形成一个短暂的"决"的姿态。

**斩击起手在动画的 1/3 处**（`AnimationProgress - useAnim / 3`）—— 前 1/3 是举剑蓄势，后 2/3 才是斩。

**音效在斩击进度 40% 处双层叠播** ✅：
```csharp
if (time >= (int)(timeMax * 0.4f) && playSwingSound)
{
    SoundEngine.PlaySound(swing  with { Volume = 0.85f, Pitch = Main.rand.NextFloat(-0.4f, -0.5f) });
    SoundEngine.PlaySound(swing2 with { Volume = 0.65f, Pitch = Main.rand.NextFloat( 0.4f,  0.5f) });
}
```
**一低一高两层**（−0.45 / +0.45），又是第 2 篇 Ion Blaster 那个和声技巧。且**音效比视觉峰值早一点**（40% 处），符合"先听到破空、后看到刀光"的直觉。

**A. 待机/蓄势期的恶魔符文**

**B. 命中时的双环**

```csharp
for (int i = ...) {
```

**C. 弹刃时的放射符文（本族最精彩的一处）** ✅
```csharp

    new CustomSpark(target.Center + launchVel * 15,
        launchVel.RotatedBy((0.15f - 0.05f * i) * (i % 2 == 0 ? -1 : 1)) * (10 + 10 * i),
```

**三重奇偶交替，全部由 `i % 2` 驱动**：
| 属性 | 偶数 `i` | 奇数 `i` |
|---|---|---|
| 偏转方向 | 逆时针 | 顺时针 |
| 额外旋转 | **90°** | 0° |
| `shrinkSpeed` | **−0.8f（横向摊开）** | **+0.8f（纵向抽长）** |

同时 `速度 = (10 + 10*i)`（越靠后越快）、`scale = 0.7 - 0.15*i`（越靠后越小）、偏转角 `0.15 - 0.05*i`（越靠后越直）。

→ **一组交错的、一半在摊开一半在抽长、左右分飞的符文碎片。** 这是"契约破碎"最贴切的视觉。用同一个粒子类和同一张贴图，靠 `i % 2` 做出两种完全相反的形变。

### 3.5 绘制：三层叠加 ✅

```csharp
// 1. 光晕层（多份重影）
Color auraColor = Color.MediumOrchid with { A = 0 } * 0.18f * (willDie ? deathFade : fadeIn);

// 2. 挥砍弧（swoosh 贴图，单份）
Main.EntitySpriteDraw(swoosh.Value, Projectile.Center + new Vector2(0, Owner.gfxOffY), null,
    Color.BlueViolet with { A = 0 } * fadeIn * 0.65f,
    (FinalRotation + MathHelper.ToRadians(45)) + MathHelper.ToRadians(swingCount % 2 == 0 ? -70 : 70) * -Owner.direction,
    swoosh.Size() * 0.5f, Projectile.scale * 0.377f, SpriteEffects.None);

// 3. 剑本体
Main.EntitySpriteDraw(tex.Value, ..., tex.Frame(1, FrameCount, 0, Frame),
    Color.Lerp(Color.MediumOrchid with { A = 0 }, lightColor, deathFade) * deathFade,
    Projectile.rotation + RotationOffset + r, ..., Projectile.scale, ...);
```

**三个要点**：
1. **`swoosh` 弧的朝向随 `swingCount % 2` 在 ±70° 间翻转** —— 左右交替挥砍时弧光方向也跟着翻，不会出现"反手挥却正手弧"的穿帮。
2. **剑本体的颜色是 `Lerp(MediumOrchid{A=0}, lightColor, deathFade)`** —— `deathFade` 为 0 时剑是**纯紫的加法发光体**，为 1 时才回到正常受光贴图。**剑在消失过程中会"烧成纯光"再消散**。
3. `fadeIn` 与 `deathFade` 用不同的 lerp 速率：
   ```csharp
   fadeIn = MathHelper.Lerp(fadeIn, 1, 0.5f);      // 出现快（0.5）
   fadeIn = MathHelper.Lerp(fadeIn, 0, 0.23f);     // 消失慢（0.23）
   ```
   **出现是消失速度的 2.17 倍** —— 快进慢出，是所有"武器召出/收起"动画的通用比例。

### 3.6 Devil's Devastation 独有：死亡印记 ✅


### 3.7 释放法评点

**三把剑的视觉差异几乎全部是"同一套粒子乘以一个系数"**：
- 屏震 5.5 → 7 → 12.5
- 环终尺寸 1.0 → 1.3 → 更大
- swoosh 缩放 0.377 → 0.455 → 更大
- 剑体 size 84 → 中 → 403

**唯一真正新增的内容是破灭魔王剑的死印**（4 道 `DevilsStrike` + `DirectStrike`）。

> **可复刻要点**：做同系列的低中高三档武器时，**先把最高档做完整，然后按系数缩小得到低档**，而不是给每档单独设计特效。玩家感知到的"更强"，90% 来自屏震、尺寸、音量这三个标量，只有 10% 来自新的特效种类。
>
> 另外，`shrinkSpeed` 的**正负号交替**（`i % 2 == 0 ? -0.8f : 0.8f`）是本族最值得偷的一招：同一个粒子类、同一张贴图，一半横向摊开、一半纵向抽长，零成本得到"破碎"的层次感。

### 4.1 资源字段 ✅

```csharp

public int AvaliableStarburst = 0;                // 当前可用量（排除处于 AICooldown 的）
public static int MaxStratusStarburst = 100;      // ✅ 官方"上限 100"的唯一来源
public float StarburstSpawnFrameCounter = 0;      // 小数累加器
public int StratusStarburstResetTimer = 0;        // 衰减保护计时器
public int Starshield = 0;                        // 层云球体的护盾时长
```

⚠️ **`MaxStratusStarburst` 是 `static`** —— 所有玩家共用同一个上限常量。

### 4.2 生成与衰减 ✅

```csharp
while (StarburstSpawnFrameCounter >= 1)
{
    StratusStarburst++;
    StarburstSpawnFrameCounter--;
}
if (Starshield > 0)
{
    Starshield--;
    StratusStarburstResetTimer = (int)MathHelper.Max(300, StratusStarburstResetTimer);
}
if (StratusStarburstResetTimer > 0)
    StratusStarburstResetTimer--;
else if (StratusStarburst > 0)
    StratusStarburst--;                            // ← 每帧掉 1 点
if (StratusStarburst > MaxStratusStarburst)
    StratusStarburst = MaxStratusStarburst;
```

**两个关键机制，官方日志一个都没提**：

1. **生成走小数累加器 `StarburstSpawnFrameCounter`**。武器每帧往里加一个小数（例如 0.3），累到 ≥1 才转成一点 Starburst。这允许"每 3 帧产 1 点"这种非整数速率，且不会因为取整而丢失精度。
2. **不使用就每帧掉 1 点**。`StratusStarburstResetTimer` 是保护期——持有层云系武器或场上有天狼星时会被不断刷新。**一旦切走武器，100 点会在 100 帧（1.67 秒）内清零。** 这是一个极其严厉的衰减，意味着 Starburst 是"即用即弃"的战斗资源，不能囤积。

`Starshield`（层云球体）强制把保护期拉到至少 300 帧，且此时 Starburst 兼作护盾值：
```csharp
public int TotalEnergyShielding => ... + (Starshield > 0 ? StratusStarburst : 0);
```

### 4.3 冷却条 UI 就是资源条 ⚠️

```csharp

    if (cooldowns.TryGetValue(Starburst.ID, out var cooldown))
```

**它复用了冷却系统来显示资源量**：`timeLeft = 100 - 当前值`。所以冷却条"走完"其实代表资源**满了**，与常规冷却语义相反。这是个很聪明的复用——不用写新 UI。

### 4.5 10 合 1 的合并机制 ⚠️（本系统最重要的设计）

```csharp
while (oneCount >= 10)
{
    var bigStar = StarburstEntities.First(x => x.value == 1);
    bigStar.value = 10;
    for (var i = 0; i < 9; i++)
    {
        var star = StarburstEntities.Last(x => x.value == 1);
        bigStar.MergeChildren.Add(star);
        star.MergeTarget = bigStar;
        StarburstEntities.Remove(star);
    }
    oneCount -= 10;
}
```

**每凑够 10 颗小星，就把第一颗升级成 `value = 10` 的大星，另外 9 颗变成它的 `MergeChildren` 并从主列表移除。**

合并动画在 `AI()` 里：
```csharp
if (MergeTarget != null)
{
    Velocity += Center.DirectionTo(MergeTarget.Center) * 2.5f;
    Velocity *= 0.925f;
    if (Center.Distance(MergeTarget.Center) < 12)
        MergeTarget.MergeChildren.Remove(this);      // 靠近到 12 像素就被吸收
    return;
}
```
**9 颗小星以加速度 2.5 飞向大星，进入 12 像素内即被吸收消失。**

**这就是为什么玩家永远不会在屏幕上看到 100 颗星**：满资源时只有 **10 颗大星**（外加合并途中的少量小星）。绘制时还有一处细节：
```csharp
var value = star.value;
value -= star.MergeChildren.Count;                    // ← 减去还没飞到的孩子
var ScaleMod = MathHelper.Lerp(0.4f, 0.8f, value / 10f);
```
**大星的尺寸只算"已吸收"的部分**，所以它是随着小星一颗颗飞入而**逐渐长大**的，不是瞬间变大。

`ScaleMod` 范围 **0.4 ~ 0.8** —— 大星只有小星的 2 倍大，克制得恰到好处。

### 4.6 跟随 AI ✅

```csharp
if (Center.Distance(owner.Center) > 100)
{
    Velocity += Center.DirectionTo(owner.Center + new Vector2(16, 0).RotatedBy(index)).RotatedByRandom(0.3f);
    Velocity *= 0.95f;
}
```
- **只有距离超过 100 像素才施加加速度** → 在玩家周围 100 像素内星星**完全自由漂浮**，不受约束。这个"死区"是星星看起来慵懒、有生命感的关键。
- 目标点是 `owner.Center + Vector2(16, 0).RotatedBy(index)` —— **每颗星按自己在列表里的下标 `index` 弧度偏移**，所以它们不会挤成一坨。
- `RotatedByRandom(0.3f)` 让每帧的加速度方向抖动 ±17°，避免直线冲刺。
- 阻尼 `0.95`（合并时是更强的 `0.925`）。

**`AICooldown > 0` 时跳过一切并清空 `MergeChildren`** —— 武器消耗 Starburst 时会把实体标记进冷却，此时它们脱离跟随、去执行攻击。

### 4.7 绘制 ✅

```csharp
Main.spriteBatch.Begin(SpriteSortMode.Deferred, BlendState.Additive, SamplerState.PointClamp,
                       DepthStencilState.None, Main.Rasterizer, null, Main.GameViewMatrix.TransformationMatrix);

// 复用天龙座的贴图，避免重复请求
var tex     = TextureAssets.Projectile[ModContent.ProjectileType<DracoConstellation>()].Value;
var glowTex = DracoConstellation.GetGlowTex();

Main.spriteBatch.Draw(glowTex, star.Center - Main.screenPosition, null, star.color * 0.66f,
                      0, glowTex.Size() * 0.5f, 0.2f * star.scale * ScaleMod, SpriteEffects.None, 1);
Main.spriteBatch.Draw(tex,     star.Center - Main.screenPosition, null, star.color * 0.66f,
                      MathHelper.WrapAngle(Main.GlobalTimeWrappedHourly + i), tex.Size() * 0.5f,
                      0.75f * star.scale * ScaleMod, SpriteEffects.None, 1);
```

- **加法混合 + `SamplerState.PointClamp`** —— 点采样，保持像素硬边（与第 0 篇 §4 的像素化审美一致）
- **辉光 0.2 缩放 + 星体 0.75 缩放**，两者都 `color * 0.66f`
- **旋转 = `WrapAngle(GlobalTimeWrappedHourly + i)`** —— 每颗星按下标 `i` 错开相位，所以整群星星的自转是**不同步的**。若不加 `+ i`，100 颗星会像齿轮一样整齐转动，非常假。
- 源码注释明说复用 `DracoConstellation` 的静态贴图 *"to prevent needless requests"*
- 6 帧动画，每 6 帧一步（`frameCounter > 6`）
- 绘制走 `ModPlayer.DrawEffects` 且判 `drawInfo.shadow == 0f`（不在残影层重复画）

| **Sirius**（第 5 篇） | 重复召唤积累 | 满 100 自动耗 **50** 放 40 倍光束 ✅ |

**官方给出的所有 Starburst 数字（100 / 10 / 20 / 4 / 50）全部是对同一个 `StratusStarburst` 计数器的加减。**

> **可复刻要点**
> - **跨武器共享资源应该做成 `ModPlayer` 上的一个 int + 一个实体列表，而不是每把武器各自维护。** 这样"上限 100"只需要改一处。
> - **"不用就掉"的衰减（每帧 −1）比"有冷却"更适合战斗资源**——它逼玩家在战斗中持续输出，而不是攒满了再切武器。
> - **10 合 1 的合并是解决"资源数量与视觉数量脱钩"的标准答案。** 资源可以有 100 点，屏幕上只需要 10 个实体。直接画 100 个会既卡又乱。
> - 跟随 AI 的 **100 像素死区**是"有生命感"的来源；加速度而非硬定位、按下标错开目标点、每帧随机抖动方向，三者缺一就会变成僵硬的编队。
