# 灾厄 2.1+ 武器特效深度拆解 · 第 0 篇：引擎底层解剖

> 本篇不讲任何一把具体武器。  
> 本篇讲的是：灾厄这套视觉表现，**在渲染管线的哪一层、由什么类、按什么数学曲线被构造出来**。  
> 后续每一篇武器拆解都会反复引用本篇定义的名词。不读本篇，后面的"它放了一个 `GlowSparkParticle`"就只是一句废话。
>
> 源码基准：本机 `ModSources/CalamityMod`，分支 `1.4.4`，最新提交 `2e10cae1c8`（build 2.2.1）。

---

## 〇、先说结论：灾厄的特效有五个层级，不是一个

新手最容易犯的错，是把灾厄的特效笼统当成"粒子"。实际上代码里有五套**互相独立、渲染时机不同、性能代价差三个数量级**的系统：

| 层级 | 系统 | 本质 | 代价 | 典型用途 |
|---|---|---|---|---|
| **L1** | 原版 `Dust` + 灾厄 `ModDust` | 引擎内建的 6000 槽位数组 | 极低 | 环境尘、枪口烟、命中碎屑 |
| **L2** | `GeneralParticleHandler` 粒子 | 灾厄自建的 `List<Particle>` + 分 BlendState 批绘制 | 低—中 | 绝大多数"好看"的武器特效 |
| **L3** | `PrimitiveRenderer` 图元带 | 动态顶点缓冲 + 自定义 `.fx` | 中—高 | 拖尾、激光束、挥砍弧 |
| **L4** | `Metaball` | 独立 RenderTarget + 边缘着色器 | 高 | 熔融/血液/虚空这类"流体团块" |
| **L5** | `ScreenShaders` / `Filters` | 全屏后处理 | 很高 | 冲击波扭曲、色差、震屏 |

**"知其所以然"的第一课**：一把武器好不好看，往往不取决于它用了多贵的层级，而取决于**它在同一时刻叠了几层**。后面会看到，灾厄最出彩的武器（如 Nanoblack Reaper、Exorcism）几乎都是 L2+L3 双层叠加，而最平庸的（如重做后的 Old Lord Claymore）只有 L1。

## 一、L2 核心：`GeneralParticleHandler` 完整解剖

文件：`Particles/GeneralParticleHandler.cs`（`[Autoload(Side = ModSide.Client)]`，纯客户端）

### 1.1 类型注册与纹理自动加载

```csharp
public override void PostSetupContent()
{
    ReflectionHelper.IterateEveryModsTypes<Particle>(action: type =>
    {
        int ID = particleIDsByTypes.Count;
        particleIDsByTypes[type] = ID;

        Particle instance = (Particle)RuntimeHelpers.GetUninitializedObject(type);

        string texturePath = type.Namespace.Replace('.', '/') + "/" + type.Name;
        if (instance.Texture != "")
            texturePath = instance.Texture;
        particleTexturesByIDs[ID] = ModContent.Request<Texture2D>(texturePath, instance.TextureRequestMode);
    });
}
```

要点：

1. **ID 是遍历顺序决定的，不是手写常量**。跨所有 mod 遍历 `Particle` 的子类，先到先得。
2. 纹理路径默认 = 命名空间转斜杠 + 类名。所以 `CalamityMod.Particles.BloodParticle` 默认找 `CalamityMod/Particles/BloodParticle.png`。
3. 想复用别人的图，就 `override string Texture`。这就是为什么 `GenericBloom`、`StrongBloom`、`BloomParticle`、`PulseRing` 四个类只用两张图（`Light.png` / `BloomCircle.png` / `HollowCircleHardEdge.png`）——**灾厄的视觉丰富度来自"同一张图 × 不同的更新曲线 × 不同的混合模式"，而不是来自海量美术资源**。这一点对我们复刻极其重要。
4. 注释里明确警告：`GetUninitializedObject` 拿到的实例**只能读 `Texture` 属性**，绝不能当真实例用。

### 1.2 `Particle` 抽象基类的全部可控面

`Particles/Particle.cs`。字段/虚属性一个不落：

**实例状态（每帧被引擎自动改写）**
- `Type` — 注册 ID，生成时自动写入，**外部禁止赋值**
- `Time` — 已存活帧数，引擎自增
- `Lifetime` — 最大帧数，配合 `SetLifetime` 才生效
- `Position` / `Velocity` / `Origin` / `Color` / `Rotation` / `Scale`
- `Variant` — 精灵表的 Y 帧号
- `RelativeOffset` — **仅在 `BaseParticleSet` 语境下有意义**，普通粒子用不到
- `LifetimeCompletion` — `Lifetime != 0 ? Time / (float)Lifetime : 0`，0→1 归一化进度。**这是所有动画曲线的自变量**

**行为开关（`virtual`，子类覆写）**
- `SetLifetime` — 默认 `false`。为 `false` 时粒子**永不自动死亡**，必须自己调 `Kill()`
- `Important` — 默认 `false`。为 `true` 时**无视粒子上限**强行生成
- `UseAdditiveBlend` — 加法混合。灾厄绝大多数发光特效开这个
- `UseHalfTransparency` — `NonPremultiplied`，被 `UseAdditiveBlend` 覆盖
- `UseCustomDraw` — 关掉默认绘制，改调 `CustomDraw(SpriteBatch)`
- `CustomShader` — 挂 `Effect`，配合 `PrepareCustomShader(Effect)` 传参
- `Pixelate` — 走像素化管线（见 §4）
- `DrawLayer` — 默认 `AfterDusts`
- `AffectedByLight` — 为 `true` 时最终颜色 `= Color.MultiplyRGB(Lighting.GetColor(Position/16))`
- `FrameVariants` — 精灵表纵向帧数，默认 1
- `TextureRequestMode` — 默认 `AsyncLoad`

**方法**
- `Update()` — 每帧调用，**在引擎已经做完 `Position += Velocity; Time++` 之后**
- `Kill()` — 等价于 `GeneralParticleHandler.RemoveParticle(this)`

### 1.3 生成路径：两个入口，语义完全不同

```csharp
public static void SpawnParticle(Particle particle, bool pixelate = false, GeneralDrawLayer? manualDrawLayerOverride = null)
{
    if (Main.gamePaused || Main.dedServ || activeParticles == null)
        return;

    if (activeParticles.Count >= CalamityClientConfig.Instance.ParticleLimit && !particle.Important)
        return;          // ← 静默丢弃！

    particle.Pixelate = pixelate;
    if (manualDrawLayerOverride.HasValue)
        particle.DrawLayer = manualDrawLayerOverride.Value;

    activeParticles.Add(particle);
    ReturnAssociatedDrawCollection(particle).Add(particle);
    particle.Type = particleIDsByTypes[particle.GetType()];
}
```

**这段代码是整个"怎么释放"命题的技术根源，必须逐条吃透：**

- **粒子上限是玩家可配的**（`CalamityClientConfig.Instance.ParticleLimit`）。超限之后，非 `Important` 粒子**不报错、不排队、直接丢弃**。
- 所以"胡乱释放一大堆"的真实后果不是掉帧那么简单：**是你自己后续那些真正关键的粒子被静默吃掉**。一把武器如果每帧喷 30 个装饰性粒子，它会亲手把自己命中瞬间的高光粒子挤出场。
- 灾厄给出的官方解法是 `FreeSpacesAvailable()`：

```csharp
public static int FreeSpacesAvailable()
{
    if (Main.dedServ || activeParticles == null) return 0;
    return CalamityClientConfig.Instance.ParticleLimit - activeParticles.Count();
}
```

注释原文写得很直白："当你需要一次性多个粒子来构成一个效果、又不希望它只画出一半时使用。"——**成组特效（环形、扇形、星座）必须先查余量再生成，否则会画出残缺的半个环。**

- `QueueParticleForNextFrame()` 存在的唯一理由：**在粒子更新循环内部生成粒子**（比如粒子 A 死亡时炸出粒子 B）。直接 `SpawnParticle` 会在遍历中修改集合。它按 `(DrawLayer, pixelated)` 分桶成 `Queue`，在下一帧 `Update()` 开头统一出队。

### 1.4 更新循环

```csharp
foreach (Particle particle in activeParticles)
{
    if (particle == null) continue;
    particle.Position += particle.Velocity;
    particle.Time++;
    particle.Update();
}

activeParticles.RemoveAll(particle =>
{
    if ((particle.Time >= particle.Lifetime && particle.SetLifetime) || particlesToKill.Contains(particle))
    {
        ReturnAssociatedDrawCollection(particle).Remove(particle);
        return true;
    }
    return false;
});
```

注意顺序：**先位移、再计时、最后才 `Update()`**。所以在 `Update()` 里读 `LifetimeCompletion` 时，读到的是"本帧结束后"的进度；第一帧就已经是 `1/Lifetime` 而非 0。做精确 4 帧判定（后面 Nanoblack Reaper 会用到）时这个 off-by-one 是致命的。

### 1.5 绘制：按 BlendState 分桶，而非按生成顺序

`ReturnAssociatedDrawCollection` 把粒子路由到 3×3 的桶里：

```
particlesToDraw_CustomShader[Effect][BlendState]   ← 有自定义 shader
particlesToDraw_Pixelated[BlendState]             ← Pixelate = true
particlesToDraw[BlendState]                       ← 普通
```

其中 `BlendState` 三选一：`Additive` > `NonPremultiplied` > `AlphaBlend`（优先级按代码里的 if-else 顺序）。

**推论（非常重要）**：同一层里，**加法混合的粒子和普通混合的粒子之间不存在可控的前后关系**——它们在两个不同的 `spriteBatch.Begin/End` 块里。你想让一个暗色轮廓压在发光核心之上，靠调用顺序是做不到的，必须靠 `DrawLayer` 或者干脆合进一个 `CustomDraw`。

普通路径：
```csharp
Main.spriteBatch.Begin(SpriteSortMode.Deferred, keyValuePair.Key, SamplerState.LinearClamp,
    DepthStencilState.None, scissorRectRasterizer, null, Main.GameViewMatrix.TransformationMatrix);
```
自定义 shader 路径改用 `SpriteSortMode.Immediate`（因为每个粒子要单独 `PrepareCustomShader`），代价明显更高。

绘制前还开了剪裁：
```csharp
Main.graphics.GraphicsDevice.ScissorRectangle = new Rectangle(0, 0, Main.screenWidth, Main.screenHeight);
```

### 1.6 一个必须知道的坑：迷幻药（trippy）四重绘制

```csharp
private static void DrawParticleInstance(Particle particle)
{
    int drawIterations = Main.LocalPlayer.Calamity().trippy ? 4 : 1;
    for (int i = 0; i < drawIterations; i++)
    {
        Vector2 positionSpoof = particle.Position;
        Vector2 positionDiff = positionSpoof - Main.LocalPlayer.Center;
        switch (i) { /* 关于玩家中心做 4 种镜像 */ }
        if (Main.LocalPlayer.Calamity().trippy)
            particle.Color = Main.DiscoColor;
        ...
        particle.Position = positionSpoof;   // 还原
    }
}
```

玩家吃了蘑菇状态后，**每个粒子被画 4 次并强制染成 `Main.DiscoColor`**。这意味着：任何依赖粒子颜色做玩法提示（比如"红色 = 满蓄力"）的设计，在该状态下完全失效。灾厄自己也没解决这个问题，但复刻时要心里有数。

### 1.7 绘制层：`GeneralDrawLayer`

`Enums/GeneralDrawLayer.cs`，`[Flags]`，9 个位：

```
BeforeAllTiles = 1<<0    BeforeSolidTiles = 1<<1   BeforeNPCs = 1<<2
AfterNPCs = 1<<3         BeforeProjectiles = 1<<4  AfterProjectiles = 1<<5
AfterPlayers = 1<<6      AfterDusts = 1<<7         AfterEverything = 1<<8
```

默认 `AfterDusts`。选层就是选"我要压在谁上面"：
- 想让特效**盖住敌人** → `AfterNPCs` 或更后
- 想让特效**被敌人挡住**（营造纵深，比如地面的余烬） → `BeforeNPCs`
- 想让特效**连 UI 之外一切都盖住** → `AfterEverything`（慎用，非常容易糊屏）

由 `Systems/Graphic/GeneralDrawLayerSystem.cs` 的 `OnDrawLayer` 事件驱动，`GeneralParticleHandler.Load()` 里挂钩。

## 二、L2 粒子原型库：15 个基本积木的精确数学

灾厄 `Particles/` 下有 **117 个 `.cs` 粒子类**。但真正被武器高频复用的只有下面这十几个。把它们的更新曲线背下来，就等于掌握了灾厄的"手感词汇表"。

### 2.1 发光球家族（三兄弟，差别全在曲线）

三个类共用同一个思路：一张径向渐变圆图 + 加法混合 + 随生命周期变化的透明度。**但曲线不同，观感完全不同。**

#### `GenericBloom` — "呼吸型"
```csharp
Texture = "CalamityMod/Particles/Light";
UseAdditiveBlend => UseAltVisual;   // 构造参数可关
SetLifetime => true;

Update():
    opacity = sin(LifetimeCompletion * π);      // 0 → 1 → 0
    Color = BaseColor * opacity;
    if (ProduceLight) Lighting.AddLight(Position, Color.RGB/255);
    Velocity *= 0.95f;
```
`sin(πt)`：**淡入 + 淡出对称**。峰值在生命中点。适合"能量在此处凝聚了一下"。
构造签名：`GenericBloom(position, velocity, color, scale, lifeTime, produceLight = true, AddativeBlend = true)`（`AddativeBlend` 是源码里的拼写错误，照抄即可）。

#### `StrongBloom` — 同曲线，换图，强制发光
```csharp
Texture = "CalamityMod/Particles/BloomCircle";
UseAdditiveBlend => true;           // 不可关
Update(): 与 GenericBloom 完全相同的 sin(πt)，但 Lighting.AddLight 无条件执行
```
额外实现了 `CustomDraw(spriteBatch, relativePosition)` 重载，**说明它被设计成可以放进 `BaseParticleSet`**。

#### `BloomParticle` — "爆开型"（会变大）
```csharp
Texture = "CalamityMod/Particles/BloomCircle";
UseAdditiveBlend => true;  UseCustomDraw => true;

Update():
    float p = PiecewiseAnimation(LifetimeCompletion,
                  new CurveSegment(EasingType.PolyOut, 0f, 0f, 1f, 4));
    Scale = Lerp(OriginalScale, FinalScale, p);
    if (Fade) opacity = sin(π/2 + LifetimeCompletion * π/2);   // = cos(t·π/2)：1 → 0
    Color = BaseColor * (Fade ? opacity : 1);
```
构造：`BloomParticle(position, velocity, color, originalScale, finalScale, lifeTime, fade = true)`

**关键差异**：
- 尺寸走 **4 次 PolyOut**（`t=0` 时增速最快，迅速逼近终值）→ 观感是"砰"地炸开然后停住
- 透明度走 **cos 四分之一周期**（`t=0` 时 opacity=1，无淡入）→ 一出现就是最亮

`sin(πt)` 和 `cos(t·π/2)` 这一对，是灾厄区分"凝聚"和"爆发"的核心手法。**用错曲线，爆炸会变成呼吸灯。**

### 2.2 冲击环家族

#### `PulseRing`
```csharp
Texture = "CalamityMod/Particles/HollowCircleHardEdge";   // 空心硬边圆环
UseAdditiveBlend => true;  SetLifetime => true;
Rotation = Main.rand.NextFloat(MathHelper.TwoPi);         // 随机初始旋转

Update():
    Scale   = Lerp(OriginalScale, FinalScale, PolyOut4(t));
    opacity = sin(π/2 + t·π/2);        // cos(t·π/2)，1 → 0
    Velocity *= 0.95f;
```
构造：`PulseRing(position, velocity, color, originalScale, finalScale, lifeTime)`

这是灾厄"冲击波"的标准件。**4 次 PolyOut 的意义**：环在前 30% 生命里就扩张到接近最终半径，剩下 70% 几乎静止只是淡出。这正好模拟真实冲击波"瞬间推开 + 缓慢消散"。如果换成线性 lerp，会变成一个匀速膨胀的肥皂泡，完全没有力量感。

#### `DirectionalPulseRing`
在 `PulseRing` 基础上加两个参数：
```csharp
public DirectionalPulseRing(position, velocity, color, Vector2 squish, float rotation,
                            originalScale, finalScale, lifeTime)
...
CustomDraw: spriteBatch.Draw(tex, ..., Rotation, tex.Size()/2f, Scale * Squish, ...);
```
`Squish` 把圆环压成椭圆，`Rotation` 由构造参数指定（不再随机）。**用途：表达"有方向的冲击"**——比如枪口的椭圆气浪、朝某个方向的爆风。`Squish = new Vector2(0.3f, 1f)` 就是一个沿垂直方向拉长的窄环。

### 2.3 火花家族（灾厄手感的灵魂）

#### `SparkParticle`
```csharp
Texture = "CalamityMod/Projectiles/StarProj";      // 复用弹幕图
UseAdditiveBlend => true;  UseCustomDraw => true;

Update():
    if (!FadeIn) {
        Scale *= 0.95f;
        Color = Color.Lerp(InitialColor, Color.Transparent, pow(t, 3));   // 三次方！
    } else {
        // 前半生命 lerp 到目标 scale（系数 0.2），后半用 -0.21 反向 lerp 收回
    }
    Velocity *= 0.95f;
    if (Velocity.Length() < 12f && AffectedByGravity) { Velocity.X *= 0.94f; Velocity.Y += 0.25f; }
    Rotation = Velocity.ToRotation() + π/2;

CustomDraw():
    Vector2 scale = new Vector2(0.5f, 1.6f) * Scale;
    spriteBatch.Draw(tex, ..., scale, ...);                        // 第一遍：外发光
    spriteBatch.Draw(tex, ..., scale * new Vector2(0.45f, 1f), ...);// 第二遍：更窄的核心
```

**三个必须理解的设计**：

1. **`pow(t, 3)` 的淡出**：三次方意味着前 60% 生命几乎不褪色（`0.6³ = 0.216`），最后 20% 断崖式消失。观感是"亮着亮着突然没了"，而非渐隐。这让高速火花看起来锐利。线性淡出会显得肉、脏。
2. **`(0.5, 1.6)` 的方向性压扁 + `Rotation = 速度方向 + π/2`**：粒子被沿运动方向拉长 3.2 倍。这就是"速度线"感的来源。
3. **同一张图画两遍**：外圈 0.5 宽 + 内圈 0.225 宽（`0.5 × 0.45`），加法混合叠加后中心亮度翻倍，形成**过曝白心 + 彩色外晕**。这是最廉价也最有效的"高能量"表现，没有任何 shader 参与。
4. **重力阈值 12f**：只有当速度降到 12 像素/帧以下才开始受重力。所以高速溅射阶段是直线，末端才开始下坠——一条抛物线的"折点"是被硬编码出来的。

#### `GlowSparkParticle`
```csharp
Texture = "CalamityMod/Particles/GlowSpark";
public Vector2 Squash = new Vector2(0.5f, 1.6f);    // 现在可配了
public bool QuickShrink; public bool Glowing; public float ShrinkSpeed = 1;

Update():
    Scale *= 0.95f;
    Color = Lerp(InitialColor, Transparent, pow(t, 3));
    Velocity *= 0.95f;
    if (QuickShrink) {
        if (ShrinkSpeed == 1) { Squash.X *= 0.8f;  Squash.Y *= 1.2f; }
        else                  { Squash.X *= (1 - 0.2f*ShrinkSpeed); Squash.Y *= (1 + 0.2f*ShrinkSpeed); }
    }
    // 同样的 12f 重力阈值
```
构造：`GlowSparkParticle(pos, vel, affectedByGravity, lifetime, scale, color, Vector2 squash, quickShrink=false, glow=true, shrinkSpeed=1)`

**`QuickShrink` 是重点**：每帧 X 乘 0.8、Y 乘 1.2，这是**指数级的横向收缩 + 纵向拉伸**。10 帧后 X 只剩 0.107 倍、Y 涨到 6.19 倍。视觉上粒子从一个小光点急速抽成一根细长的针，然后消失。这就是灾厄那些"能量被抽走/激光余烬"效果的做法。

`Glowing` 为 true 时同样是双绘制（第二遍 `Vector2(0.45f, 1f)` 且颜色向白色插值）。

彩蛋：`Main.zenithWorld` 且现实时间是星期二时，纹理会被换成 `MammothParticle`（猛犸象）。**这是真的在代码里**，复刻时不用抄。

#### `SquareParticle`
```csharp
Texture = "CalamityMod/Particles/Square";
UseAdditiveBlend => true;
Update(): Scale *= 0.95f; Color 三次方淡出; Velocity *= 0.95f; 12f 重力阈值;
          Rotation = Velocity.ToRotation() + π/2 + ExtraRotation;
```
和 `SparkParticle` 同一套物理，只是画的是方块、且单次绘制。**用途：科技/数据/硬光质感**（Draedon 系武器、Nanoblack Reaper 大量使用）。方块 + 加法混合 = 立刻有"数字化"味道，和有机的火花形成鲜明对照。

### 2.4 单帧重绘型：挥砍与线条

这一类的 `Lifetime` 只有 **2 帧**。它们不是"存活的粒子"，而是**由持有者每帧重新生成一个新实例**——本质上是一种借粒子系统做的即时绘制。

#### `CircularSmearVFX`
```csharp
Texture = "CalamityMod/Particles/CircularSmear";
UseAdditiveBlend => true;  UseCustomDraw => true;
Lifetime = 2;
public Asset<Texture2D> LoadedAsset;     // 可换图！

CircularSmearVFX(position, color, rotation, scale, texture = null)
    → texture 为 null 时用 ExtraTextureRefs.CircularSmear
```
这是**近战挥砍残影**的标准件。可换的贴图在 `Particles/` 下备好了一组：
`CircularSmear.png` / `CircularSmearLarge.png` / `CircularSmearFire1~3.png` / `CircularSmearSmokey.png` / `ArchSmear.png` / `CircularTrail.png`

同族还有 `SemiCircularSmearVFX`、`SemiCircularSmearFade`、`TrientCircularSmearVFX`（三分之一弧）、`CircularSmearSmokeyVFX`。

**释放法**：在剑的 `AI()` 里每帧算出当前挥砍角度，生成一个 `CircularSmearVFX(玩家中心 + 偏移, 颜色, 当前角度, 尺寸)`。因为 Lifetime=2，上一帧的还没死、这一帧的又来了，视觉上就是连续的弧光。**尺寸和颜色随挥砍进度插值，就得到"起手细→中段最亮→收尾淡"**。

#### `LineVFX`
```csharp
Texture = "CalamityMod/Particles/ThinEndedLine";   // Concave 时改用 ThickEndedLine
UseAdditiveBlend => true;  UseCustomDraw => true;
Lifetime = 2;
Important => Telegraph;      // 当作敌人预警线时无视粒子上限

LineVFX(startPoint, lineVector, thickness, color, concave = false, telegraph = false, expansion = 0f)

CustomDraw():
    float ease = sqrt(1 - pow(LifetimeCompletion - 1, 2));    // 圆形缓动
    Vector2 drawPosition  = Position - normalize(LineVector) * ease * Expansion / 2f;
    Vector2 expandedLine  = LineVector + normalize(LineVector) * ease * Expansion;
    float rot    = LineVector.ToRotation() + π/2;
    Vector2 origin = new Vector2(tex.Width/2f, tex.Height);          // 原点在底边中点
    Vector2 scale  = new Vector2(Scale, expandedLine.Length()/tex.Height);
```

**`sqrt(1 - (t-1)²)` 是四分之一圆弧缓动**：t=0 时为 0，t=1 时为 1，且导数在 t=0 处无穷大 → **瞬间弹出，然后减速到位**。用于"线从中心刷地射出去"。

`Important => Telegraph` 这个设计值得学：**预警线关乎玩家生死，绝不能因为屏幕上装饰粒子太多而被丢弃**。我们复刻时，凡是承载玩法信息的粒子都应该这么标。

同族：`AltLineParticle`、`LineParticle`、`StaticGlowLine`、`BloomLineVFX`、`ChargeUpLineVFX`。备用贴图：`BloomLine.png` / `BloomLineAngled.png` / `BloomLineFade.png` / `BloomLineSkinny.png` / `BloomLineSoftEdge.png` / `BloomLineThick.png` / `FadeLine.png` / `FadeStreak.png` / `DrainLine.png`。

## 三、L3：`PrimitiveRenderer` 图元带

文件：`Graphics/Primitives/PrimitiveRenderer.cs` + `PrimitiveSettings.cs`

### 3.1 用法

```
在弹幕/NPC 的 PreDraw 里调 PrimitiveRenderer.RenderTrail(positions, settings, pointCount, render)
若要像素化，必须让类实现 IPixelatedPrimitiveRenderer，
并把绘制写在 RenderPixelatedPrimitives 里（不是 PreDraw），
可选用 IPixelatedPrimitiveRenderer.LayerToRenderTo 指定层（默认 BeforeNPCs）
```

### 3.2 `PrimitiveSettings` 全参数

三个委托是核心：
```csharp
delegate float   VertexWidthFunction (float trailLengthInterpolant, Vector2 vertexPosition);
delegate Color   VertexColorFunction (float trailLengthInterpolant, Vector2 vertexPosition);
delegate Vector2 VertexOffsetFunction(float trailLengthInterpolant, Vector2 vertexPosition);
```
`trailLengthInterpolant` 是 0（拖尾头部）→1（尾部）。**拖尾的一切形状都由 `WidthFunction` 决定**——想要"头粗尾尖"就写 `t => baseWidth * (1 - t)`，想要"梭形"就写 `t => baseWidth * sin(t * π)`。

其余字段（构造函数默认值一并列出，复刻时这是硬约束）：

| 参数 | 默认 | 作用 |
|---|---|---|
| `Smoothen` | `true` | 是否对控制点做样条插值 |
| `Pixelate` | `false` | 走像素化管线 |
| `Shader` | `null` | `MiscShaderData` |
| `UseUnscaledMatrices` | `false` | 在 CustomSky 等非常规语境下才开 |
| `InitialVertexPositionsOverride` | `null` | 强制指定首个顶点的左右两侧屏幕坐标 |
| `TextureCoordinateMode` | `Normalized` | `Normalized`（U 跑 0→1）/ `Distance`（每 N 像素一个循环） |
| `TextureCycleLength` | `1f` | Normalized 下是倍率；Distance 下是每循环像素数 |
| `TextureScrollOffset` | `0f` | U 偏移（Distance 模式下单位为像素）→ **滚动纹理靠它做** |
| `TextureCoordinateFunction` | `null` | 完全接管 U 生成 |
| `JoinStyle` | `Smooth` | `Flat` / `Smooth`（相邻切线平均）/ `Miter`（斜接，保宽） |
| `JoinMiterLimit` | `4f` | 最小被钳到 1f |
| `SmoothingType` | `CatmullRom` | 另有 `Cardinal` / `Linear` / `Hermite` / `CubicBezier` |
| `SmoothingSegments` | `0`（自动） | 每段控制边的细分数 |
| `SmoothingTension` | `0f` | Cardinal 用 |
| `FrameTransportMode` | `ParallelTransport` | 或 `Basic`（用瞬时切线，会扭） |
| `Topology` | `TriangleStrip` | 或 `TriangleList` |
| `CapStyle` | `None` | 或 `Flat`（端头加三角封口） |
| `DebugWireframe` / `WireframeColor` | `false` / `LimeGreen` | 调试线框 |

### 3.3 硬性容量上限

```csharp
private const short MaxPositions = 1000;
private const short MaxVertices  = 3072;
private const short MaxIndices   = 8192;
```
**超过就画不出来。** 一条 `TriangleStrip` 拖尾每个采样点产生 2 个顶点，所以单条拖尾的有效采样点上限约 1536。做超长激光或多重折线时必须留意。

## 四、像素化管线

`Systems/Graphic/PixelationSystem/` + `Graphics/Primitives/PrimitivePixelationSystem.cs` + `Effects/pixelation.h`

粒子侧：`SpawnParticle(particle, pixelate: true)`，随后 `PixelationManager.AddPixelatedDrawer(drawer, drawLayer, blendState)`。
图元侧：`PrimitiveSettings.Pixelate = true` + 实现 `IPixelatedPrimitiveRenderer`。

原理：先画到一张**低分辨率 RenderTarget**，再放大回屏幕，从而让平滑的矢量图元强行落到 Terraria 的像素栅格上。

**这是审美层面的决定，不是性能优化。** 灾厄的科技系武器（Draedon 军械库、Exo 系）几乎全开像素化，因为不开的话高分辨率光带会和 Terraria 的像素画风格格不入。有机系（血、火、虚空）反而多数不开，保留柔和边缘。**复刻时选错，武器会立刻"不像灾厄"。**

## 五、L4：Metaball 流体

`Graphics/Metaballs/Metaball.cs` + `MetaballManager.cs`

抽象成员：
- `AnythingToDraw`（性能短路，没内容就整套跳过）
- `Layers`（叠在团块之上的纹理序列）
- `LayerColors`（`List<Vector4>`，缺省白）
- `DrawLayer`
- `EdgeColor`（空气与团块交界处的描边色）
- `FixedToScreen`（false 时纹理随 `Main.screenPosition` 视差滚动）
- `IgnoreFPS`（按绘制周期而非逻辑周期更新）
- `PrepareSpriteBatch` / `PrepareShaderForTarget` / `CalculateManualOffsetForLayer` / `ClearInstances` / `Update`

`PrepareShaderForTarget` 里给 `CalamityShaders.MetaballEdgeShader` 传：
`layerSize` `screenSize` `layerOffset` `edgeColor` `singleFrameScreenOffset` `layerColor`，并把层纹理绑到 `gd.Textures[1]`、采样器设 `LinearWrap`。

已有 20+ 个实现（`BloodMetaball` `CataclysmMetaball` `StarsmokeMetaball` `SeekersMetaball` `SignusMetaball` `GalaxyMetaball` `GruesomeMetaball` `StreamGougeMetaball` `RancorLavaMetaball` `BigRipMetaball` `DragonsBreathMetaball` `BloodBoilerMetaball` `VoidGeneratorMetaball` `PhotoMetaball1~4` `PaintMetaballs` `ScalArenaMetaball` `DoGDistortionMetaball` …）。

**什么时候该用 Metaball**：当你要表达的东西是**会融合的连续介质**——两团血靠近会合成一团、熔岩流会拉丝。普通粒子做不到"融合"，只能做到"重叠"。这是唯一的判断标准。代价是每个 Metaball 至少一张全屏 RT。

## 六、L1：Dust 层

原版 `Dust.NewDust` / `Dust.NewDustPerfect` / `Dust.NewDustDirect`，加上灾厄自己的 `ModDust`（`Dusts/` 下约 25 个，如 `BrimstoneFlame` `AstralBasic/Blue/Orange` `HolyFireDust` `VoidDust` `VoidDustInverted` `CeaselessDust` `AuricBarDust` `CosmiliteBarDust` `ShadowspecBarDust` `UnstableDust` `TerraSigilDust` `FinalFlame` `AdrenDust` `AbsorberDust` `SquareDust` …），ID 常量集中在 `Dusts/CalamityDusts.cs`。

Dust 的定位在 2.1 之后已经很明确：**做"量"，不做"质"**。
- 需要 50 个廉价碎屑铺满一片区域 → Dust
- 需要 3 个有精确曲线、有辉光、有方向拉伸的高光 → Particle

灾厄 2.1 重做的大方向之一，就是把老武器里"喷一堆 dust"换成"少量精确 particle + 少量 dust 打底"。这直接对应用户提出的那句话：**胡乱释放一大堆，和精准释放一点点，给人的感觉完全不一样。**

## 七、贯穿全篇的方法论：怎么读一把武器的特效

后续每一篇拆解，我都按这个固定顺序走，请对照阅读：

1. **实体拓扑**：这把武器一共有几个 `ModProjectile`？谁生谁？（Holdout → 子弹 → 命中产物 → 二级产物）
2. **每个实体的视觉构成**：贴图本体 / 拖尾（L3？什么 shader？什么 WidthFunction？）/ 光晕（L2 哪个原型？）/ 尘（L1？多少个？）
3. **释放时机与数量**：写死的常数、随蓄力/层数缩放的公式、`Main.rand` 的介入位置、有没有查 `FreeSpacesAvailable()`
4. **节拍**：一次完整攻击循环里，视觉密度的起伏曲线（哪里安静、哪里爆发）
5. **可复刻性评估**：哪些是官方日志确证的硬数值，哪些是我从源码读出来的实测值，哪些仍然是"未公开/需实测"
