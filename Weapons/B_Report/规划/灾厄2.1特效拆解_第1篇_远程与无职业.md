## 通用底座：`BaseGunHoldoutProjectile`

2.1 重做的枪械几乎全部改成了 **holdout 弹幕**——玩家手里那把枪本身是一个 `ModProjectile`，而不是物品贴图。这是理解本篇所有武器的前提。

文件：`Projectiles/BaseProjectiles/BaseGunHoldoutProjectile.cs`

子类可覆写的关键量：

| 成员 | 含义 |
|---|---|
| `AssociatedItemID` | 绑定的物品，手上换东西就自杀 |
| `MaxOffsetLengthFromArm` | 枪相对手臂的基础前伸距离 |
| `OffsetLengthFromArm` | **当前**前伸距离。开火时减去一个值 → 后坐力 |
| `RecoilResolveSpeed` | 每帧向 `MaxOffsetLengthFromArm` lerp 的系数 → 后坐恢复速度 |
| `OffsetXUpwards` / `OffsetXDownwards` / `BaseOffsetY` / `OffsetYUpwards` / `OffsetYDownwards` | 按枪口仰角重映射的手持偏移 |
| `GunTipPosition` | 枪口世界坐标，**所有枪口特效的锚点** |
| `FrontArmStretch` / `BackArmStretch` / `ExtraFrontArmRotation` / `ExtraBackArmRotation` | 复合手臂姿态 |
| `HoldoutAI()` / `ManageHoldout()` / `KillHoldoutLogic()` | 三个生命周期钩子 |

**后坐力的实现是纯视觉的位移，不是屏幕震动**：
```csharp
OffsetLengthFromArm -= 25f;                                        // 开火瞬间猛缩
OffsetLengthFromArm = MathHelper.Lerp(OffsetLengthFromArm, MaxOffsetLengthFromArm, RecoilResolveSpeed);  // 每帧回弹
```
`RecoilResolveSpeed` 越小回弹越慢、后坐越"重"。极乐升天炮是 `0.07f`（很重），地狱降临是 `0.5f`（很脆）。**这一个浮点数就决定了枪的重量感**，比任何粒子都重要。

屏幕震动另有其人：`Owner.SetScreenshake(float)`。极乐 5f、腐臭 6.5f、地狱降临 5f。

## 1. Arterial Assault / 血陨 / 远程

### 实体拓扑
```
ArterialAssault (物品，无 holdout，直接 Shoot 覆写)
  └─ BloodfireArrowProj × 5          （DisableEffects = true）
       └─ [命中] BloodstoneHealOrb    （由 CalamityGlobalProjectile.BloodstoneOrbValue 触发）
```

### 齐射几何 ✅
```csharp
float rotateBy = 0.75f * ((shotNum * 3) % 5 - 2);
position += velocity.SafeNormalize(Vector2.Zero).RotatedBy(rotateBy) * 64;
velocity = position.DirectionTo(Main.MouseWorld) * velocity.Length() * 2;
```
- `useTime = 6`、`useAnimation = 40`、`useLimitPerAnimation = 5`、`reuseDelay = 10` → **每轮正好 5 箭**（对应官方"5 支血箭"）
- `shotNum` 0→4 循环，`(shotNum*3) % 5 - 2` 产生序列 `-2, 1, -1, 2, 0`，乘 0.75 得 **{-1.5, 0.75, -0.75, 1.5, 0} 弧度**
- **这不是均匀扇形，而是"左右横跳"的发射顺序**：先最左、再右、再左、再最右、最后正中。生成点在玩家前方 64 像素处、沿该角度偏移，然后**每支箭各自重新瞄准鼠标** → 五条射线从五个不同起点汇聚到同一目标点，形成"合围"而非"散开"。
- 速度 `shootSpeed = 30f` 再 `× 2` = 60，但箭生成后立刻被 `SafeNormalize * 9` 覆盖，配合 `extraUpdates = 9`（每帧 10 次更新）→ **等效 90 像素/帧**
- `tileCollide = false`、`conditionalHomingRange = 175f`（小范围索敌，对应"小范围索敌"）

### 视觉构成
**箭本体**：`Texture => "CalamityMod/Items/Ammo/BloodfireArrow"`，`TrailCacheLength = 10`、`TrailingMode = 1`，`PreDraw` 走 `CalamityUtils.DrawAfterimagesCentered(Projectile, 1, Color.White, 2)` — **纯残影堆叠，没有图元带**。

**飞行拖尾**（`localAI[0] > 6f && 距玩家 < 1400f` 才生成，即离手后才开始）：
- 50% 概率每帧 1 个 dust：`Main.rand.NextBool(3) ? 130 : 60`（1/3 概率 130 号，否则 60 号），速度 `-velocity.RotatedByRandom(0.5f) * rand(0.2, 0.6)`，`noGravity = true`，scale `rand(0.3, 0.7)`（130 号时改 `rand(0.25, 0.45)`）
- 每 2 帧 1 个 `CustomSpark`：贴图 `BloomLineFade`，生命 6 帧，scale **0.025f**（极小），`shrinkSpeed: 1.4f`，`glowOpacity: 0.4f`，位置 `Center - velocity * 2`
  - `shrinkSpeed 1.4` 代入 `CustomSpark.Update` 的 `Stretch.X *= (1 - 0.2*1.4) = 0.72`、`Stretch.Y *= (1 + 0.2*1.4) = 1.28` → **每帧横向砍掉 28%、纵向拉长 28%**，6 帧内抽成一根极细的针
- **颜色受 `ChildSafety.Disabled` 控制**：血腥关闭时是 `Color.CornflowerBlue`，开启时 `Color.Firebrick`。整个武器所有颜色都走这个三元判断。

**消散**（`OnKill`）：6 个 `DiamondDust`，速度 `(velocity * 2).RotatedByRandom(0.3) * rand(0.1, 0.75)`，scale `rand(0.75, 0.95)`，`fadeIn = 15`，且 `noLight = noLightEmittence = true`（**不发光，靠 fadeIn 做"结晶浮现"感**）。

### 血球：这是 Metaball，不是粒子 ⚠️
`shotArrow.Calamity().BloodstoneOrbValue = 15` → 命中时由 `CalamityGlobalProjectile:4869` 生成 `BloodstoneHealOrb`：

```csharp
Projectile.NewProjectile(..., projectile.velocity.SafeNormalize(Vector2.Zero)
    * Math.Min((projectile.velocity.Length() * projectile.MaxUpdates) / 4f, 4f)
    * Main.rand.NextFloat(0.75f, 1.25f), ModContent.ProjectileType<BloodstoneHealOrb>(), BloodstoneOrbValue, ...);
```

`BloodstoneHealOrb` 本体 `Texture => "InvisibleProj"`、`PreDraw` 直接 `return false` — **它自己完全不可见**。可见的是它每帧往血液 Metaball 里注入的采样点：

```csharp
var p = BloodMetaball.SpawnParticle(Projectile.Center + Projectile.velocity, Main.rand.NextVector2Circular(-0.5f, -0.5f), Projectile.width);
p.SizeScaling = 0.75f;
p.ShrinkDelay = 1;
```

**这就是血球看起来"黏稠、会互相融合"的根本原因**——它走的是 L4 metaball 管线（RenderTarget + 边缘着色器），不是粒子。多个血球靠近时轮廓会真正合并。用普通粒子永远做不出这个效果。

其余参数 ✅：
- `extraUpdates = 3`、`timeLeft = 60*5*MaxUpdates`（5 秒）
- `spawnCooldown = 60 * MaxUpdates` → **生成后 15 帧（0.25 秒实时）内不可拾取**
- 吸附半径 200f（有 Heartreach 时 `×2.25` = 300f）
- 靠近后 `velocity = (velocity*5 + 方向*5) / 6f`，50f 内且矩形重叠才结算

**治疗结算**（`BloodstoneHealOrb.Heal`）：
```csharp
if (player.potionDelay > 0) { player.potionDelay -= PotionTime; ... }
else player.lifeRegenTime += 3 * PotionTime;
```
`PotionTime = BloodstoneOrbValue = 15` 帧 = **0.25 秒** ✅ —— 与官方"每球令药水病减 0.25 秒"完全吻合。无药水病时改为 `lifeRegenTime += 45`。

拾取瞬间的唯一粒子：
```csharp
new CustomPulse(player.Center, Vector2.Zero, (血腥色) * 0.75f, "CalamityMod/Particles/DustyCircleHardEdge",
                Vector2.One, 0, 0.01f, 0.05f, 20);
```
一个从 scale 0.01 涨到 0.05、生命 20 帧的小环。**极其克制**——一个治疗反馈只用一个环。

### 释放法评点
天降层被砍掉后，整把武器的视觉密度**大幅下降**：飞行期每帧最多 1 dust + 每 2 帧 1 个 scale=0.025 的微型火花。这是刻意的——真正的视觉重心放在**命中后涌出的 metaball 血球**上。
> **可复刻要点**：`0.025f` 的 scale 不是笔误。灾厄用"大量极小的高频火花"而非"少量大火花"来做高速拖尾，因为前者在 90 px/frame 的速度下才不会糊成一片。

## 2. Blissful Bombardier / 极乐升天炮 / 远程

### 实体拓扑
```
BlissfulBombardier (物品)
  └─ BlissfulBombardierHoldout (枪本体)
       └─ NukeOfBliss (主导弹，1 枚，竖直上升)
            ├─ BlissfulBombardierSplitProjectile × 2/次（集束火箭为 ×4）
            └─ [OnKill] 大爆炸
```

### 三阶段节拍 ✅

**阶段 A — 蓄势/上升**
- `shootingTimer` 每帧 +1，到 `Owner.itemAnimationMax` 时开火
- 开火前的 `PreDraw` 充能表现：**10 个方向的贴图重影环**
  ```csharp
  float fade = Utils.GetLerpValue(0, Owner.itemAnimationMax, shootingTimer, true);
  for (int i = 0; i < 10; i++) {
      Vector2 drawOffset = (MathHelper.TwoPi * i / 10f).ToRotationVector2() * 5 * fade;
      Draw(texture, drawPosition + drawOffset, staticEffectsColor with { A = 0 } * fade, ...);
  }
  ```
  半径 **5 像素**、**10 份**、`A = 0`（加法感）、强度随 `fade` 增长。这是"武器自己在发光/震动"的最廉价做法——不用任何粒子，只是把枪贴图沿圆周画 10 遍。**极其值得抄。**

**开火瞬间的枪口** ✅：
- **26 个 dust**（`for i = 0; i <= 25`），奇偶分流：
  - 偶数（13 个）：`LightDust`，速度 `(velocity*12).RotatedByRandom(0.6f) * rand(0.4, 1.7)`，scale `rand(1.8, 2.3)`，`noGravity`，颜色 1/3 概率 `Orange` 否则 `effectsColor`，`noLightEmittence = true`
  - 奇数（13 个）：`DustID.FireworksRGB`，同速度公式，scale `rand(1.2, 1.6)`，**有重力**，颜色 1/3 `Orange` 否则 `staticEffectsColor`
- **6 个 `DirectionalPulseRing`**：
  ```csharp
  float pulseScale = Main.rand.NextFloat(0.2f, 0.4f);
  new DirectionalPulseRing(GunTipPosition, (shootDirection*20).RotatedByRandom(0.25f) * rand(0.5,1.2),
      (1/3概率 effectsColor : staticEffectsColor) * 0.8f, new Vector2(1,1),
      pulseScale - 0.25f, pulseScale, 0f, 20);
  ```
  注意 `originalScale = pulseScale - 0.25f` 可能是**负数**（当 pulseScale < 0.25 时）→ 环会先"内翻"再展开。这是个 bug 还是特性不好说，但观感上产生了随机的闪烁差异。
- `Owner.SetScreenshake(5f)`、`OffsetLengthFromArm -= 25f`

**颜色由弹药决定** ✅（`dustEffectsID` / `effectsColor`，`staticEffectsColor` 恒为 `Color.Khaki`）：
| 火箭 | dustEffectsID | effectsColor |
|---|---|---|
| WetRocket | 45 | `RoyalBlue` |
| LavaRocket | `DustID.Torch` | `Red` |
| HoneyRocket | `DustID.Honey` | `Yellow` |
| 其他（默认） | 87 | `Goldenrod` |

**阶段 B — 主导弹上升与光标区降火**
`NukeOfBliss`：`extraUpdates = 2`、`timeLeft = 700`、`penetrate = -1`、`localNPCHitCooldown = 20`
- `reachedPeakTime = 120`、`rainDownTimer = 150`（初值）
- `time <= 120` 时：`velocity *= 0.995f`（缓慢减速上升）
- `time > 120` 且 `rainDownTimer > 1`：**导弹被强制传送到 `(鼠标X, 玩家Y) + (0, -600)`** —— 也就是它不是真的飞过去，是瞬移到光标正上方 600 像素处挂着
- `rainDownTimer >= 80` 且 `% 15 == 0` 时发射分弹：
  - 普通火箭 **2 枚/次**，集束火箭 **4 枚/次**
  - 生效窗口 `rainDownTimer` 从 150 降到 80，每 15 帧一次 → **命中 150/135/120/105/90 共 5 次** → **普通共 10 枚小圣火，集束共 20 枚** ✅（官方"小火数未公开"，这里给出了）
  - 伤害倍率：普通 `0.3f`，集束 `0.15f`
  - 散布 `variance = (i%2==0 ? 0.2f : 1) * (new Vector2(80 * (集束?3:1), 0) * rand(-1,1))`，速度 `方向 * rand(8,12) + variance*0.008f`
- `rainDownTimer == 65` 时连播 **3 次** `MissileNearing` 音效（`Volume 0.6, Pitch 0.4, MaxInstances 2`）—— 预警
- 拖尾：`fade > 0.2f` 时每帧 1 个 `HeavySmokeParticle`（`staticEffectsColor`，生命 `rand(40,61)`，scale `rand(0.3,0.6)`，`required: true` **无视粒子上限**）
- 本体绘制：`Projectile.DrawProjectileWithBackglow(staticEffectsColor with {A=0} * fade2, lightColor * fade2, 6f * GetLerpValue(0, 120, time), texture)` —— **背光半径随上升时间从 0 长到 6**

**阶段 C — 末端俯冲与大爆炸**
- `rainDownTimer == 1`：`extraUpdates = 10`（速度暴涨 5 倍）、`penetrate = 1`、朝目标/鼠标 `* 15`
- `rainDownTimer == 0`：每帧 1 个 `SparkParticle(Center, -velocity*0.05f, false, 19, 1.7f, Color.Goldenrod)`，并做弱追踪（速度 <15 时 `velocity*0.98 + 方向*2.5`，否则 `*0.9`）

**`OnKill` 爆炸** ✅（这是全武器视觉最密集处）：
```
blastRadius       = Clamp(RocketBehavior(info), 3, 100)
blastRadiusVisual = blastRadius * 0.5f
```
- 2 个 `CustomPulse`（`SoftRoundExplosion` 贴图）：`staticEffectsColor` @ `0.07f * blastRadiusVisual`，`effectsColor` @ `0.05f * blastRadiusVisual`，生命 19
- 3 个 `CustomPulse`（`SmallBloom`）：`Color.Orchid` @ `0.45f * blastRadiusVisual`，生命 15
- **40 个 `LightDust` 完美均分圆周**：
  ```csharp
  c.velocity = (MathHelper.TwoPi * i / 40f).ToRotationVector2() * 8.5f * (i%2==0 ? 0.88f : 1f) * blastRadiusVisual;
  c.scale    = rand(0.3,0.6) * blastRadius * 0.3f * (i%2==0 ? 2.2f : 1.8f);
  ```
  **奇偶交替的 0.88/1.0 速度 + 2.2/1.8 尺寸 → 形成"双层同心冲击环"**，比 40 个同速 dust 有层次得多。这是本武器最值得学的一招。
- 14 个 `CustomSpark`（`ProvidenceMarkParticle` 贴图），生命 27，scale `rand(2.45, 2.7)`，颜色 `Lerp(Orchid, White, rand(0,0.7))`，`stretch (1.3, 0.5)`，`shrinkSpeed rand(0.35, 0.4)`
- 11 个 `DustID.FireworksRGB`（有重力）
- 15 个 `CustomSpark`（**贴图直接借用 `Projectiles/Boss/ProvidenceCrystal`**），生命 12，scale `0.15f * blastRadius`，`stretch (1.5, 0.4)`，`shrinkSpeed 0.7f`
- 两个音效叠播：`MineralMortarExplode`（Pitch 0.4）+ `BlazingCoreParry`

**伤害衰减** ✅：`ModifyHitNPC` 里 `Remap(numHits, 0, 10, 1, 0.35f)`，且下落阶段（`rainDownTimer > 0`）额外 `× 0.2`。

### 释放法评点
这把武器是"**三段式密度曲线**"的教科书：
1. 蓄势期（0 粒子，只有 10 份贴图重影）
2. 发射（26 dust + 6 环，一次性）
3. 巡航（每帧 1 烟，极稀）
4. 降火期（每 15 帧 2 枚分弹，稀疏但有节奏 + 3 声预警）
5. 终爆（约 **125 个视觉实体**一次性释放）

**安静的中段是为了让终爆显得大。** 如果巡航期也喷 20 个粒子，终爆就完全没有冲击力了。这正是用户说的"精准释放"的实例。

## 3. Fetid Emesis / 腐臭倾泻者 / 远程

### 实体拓扑
```
FetidEmesis (物品) └─ FetidEmesisHoldout └─ 原版子弹 ×N / EmesisGore × 11
```

### 加速曲线 ✅
```csharp
maxFrames = 420;  initialFireTime = 45;
revSpeed = Utils.Remap(revFrames, 0, maxFrames - 120, 1, 20, true);   // 即 0→300 帧映射到 1→20
shootingTimer += revSpeed;    // 不是 +1！
```
- `revFrames` 从 0 涨到 **300 帧 = 5 秒**时 `revSpeed` 达到上限 20 ✅ —— 精确对应官方"连射在 5 秒内加速"
- 射击判定用 `shootingTimer >= 60`（主弹）和 `shootingTimer >= initialFireTime(45)`（副弹，`secondShot` 门控）。因为 `shootingTimer` 每帧加 `revSpeed`，所以**射速 = revSpeed/60 发每帧**，从 1/60 涨到 1/3
- 散布 `spread = 0.045f * GetLerpValue(0, 420, revFrames)` → 越热越散，最大 0.045 弧度（约 2.6°）；副弹再额外 `RotatedByRandom(0.04f)`
- 副弹伤害 `Projectile.damage / 2`

### 满热爆发 ✅
`revFrames >= 420`（7 秒）时：
- **11 枚 `EmesisGore`**（官方确证 11 ✅），生成方式：
  ```csharp
  velBonus = 1.1f;
  for (i = 0..5)  → RotatedBy(-0.03f * i * velBonus) * (1 - i*0.08f) * velBonus,  ai0 = -i
  for (j = 0..5)  → RotatedBy(+0.03f * j * velBonus) * (1 - j*0.08f) * velBonus,  ai0 = +j
  额外 1 枚 → 正前方 * velBonus, ai0 = 20
  ```
  注意 `i=0` 和 `j=0` 都是正前方 → **实际是 6 + 6 + 1 = 13 次生成，但 i=0/j=0 重合**，官方口径记 11。散角 `±0.03 * 5 * 1.1 = ±0.165 弧度`（约 ±9.5°），**外侧的飞得慢**（`1 - 5*0.08 = 0.6` 倍速）→ 形成前快后慢的锥形散布
  - 伤害 `Projectile.damage * 2.5f` ✅（官方 250%）
- 枪口：
  - 1 个 `GlowSparkParticle(GunTipPosition - shootVelocity, shootVelocity, false, 12, 0.035f, Color.Chartreuse, new Vector2(2.5f, 0.9f), true)` —— `quickShrink = true`，`squash(2.5, 0.9)` 是**横向拉宽**的（不同于默认的纵向拉长）
  - 1 个 `CustomPulse`（`DustyCircleHardEdge`）：`Chartreuse * 0.7f`，squish `(0.4, 1)`，速度 `velocity * 14.5f`，生命 34
  - 1 个 `CustomPulse`（`FlameExplosion`）：同色，squish `(0.4, 1)`，速度 `velocity * 9f`，scale 0.25，生命 34
  - 19 个 `DustID.RainbowTorch`（`i <= 18`），染 `Chartreuse`，散布 0.3
- `Owner.SetScreenshake(6.5f)`、`OffsetLengthFromArm -= 35f`
- 双音效：`PerfHiveIchorShoot`（Pitch -0.2）+ `FlakKrakenShoot`

### 冷却 ✅
```csharp
cooldownTimer = (int)MathHelper.Lerp(Remap(revFrames, 0, 350, 40, 180, true), 180, 0.7f);
```
满热时 `Remap` 已达 180，再 `Lerp(180, 180, 0.7)` = **180 帧 = 3 秒** ✅（官方"3 秒锁枪"）。
未满热提前松手时：`cooldownTimer = Remap(revFrames, 0, 350, 40, 180)` → **40~180 帧线性**，热度越高罚越久。

冷却期表现（每 **29 帧**一次）：
- `OldDukeHuff` 音效（Pitch -0.2）
- 13 个 `DustID.SteampunkSteam`（`i <= 12`），白色，有重力
- 5 个 `HeavySmokeParticle`（白色，`required: true`）
同时 `revFrames *= 0.7f` 每帧衰减 → 指数散热。

### 持续视觉：两套叠加的"过热光环" ✅
**A. 24 份贴图环绕重影**（`PreDraw`）
```csharp
float attackLerp = Math.Pow(Utils.GetLerpValue(60, 200, revFrames, true), 8);   // 8 次方！
float mult       = Math.Max(GetLerpValue(7, 0, i), GetLerpValue(17, 24, i));
float outspace   = 6 * attackLerp;
Vector2 drawOffset = (TwoPi * i / 24f).ToRotationVector2().RotatedBy(Projectile.rotation) * outspace
                     + Main.rand.NextVector2Circular(2, 2);
Color auraColor  = Color.Chartreuse with { A = 0 } * mult * 0.4f * GetLerpValue(90, 135, revFrames, true);
```
- **8 次方曲线**：`revFrames` 从 60 到 200 归一化后取 8 次方 → 前 80% 几乎为 0，最后 20% 暴涨。观感是"热度到某个点后突然开始外溢"，而不是线性变亮。
- `mult` 的写法很妙：`i` 在 0~7 时 `GetLerpValue(7,0,i)` 从 1 降到 0；`i` 在 17~24 时 `GetLerpValue(17,24,i)` 从 0 升到 1；中间 8~16 两者都是 0 → **光环只出现在圆周的一段弧上（i≈0 和 i≈24 附近，即枪口正前方），中段是空的**。配合 `RotatedBy(Projectile.rotation)`，这是一个**朝枪口方向偏置的半环**，不是均匀光晕。
- 每份还叠 `NextVector2Circular(2, 2)` 的随机抖动 → 沸腾感

**B. 枪口星芒**（`shineScale` 驱动）
```csharp
shineScale = 1;          // 每次开火置 1
shineScale *= 0.77f;     // 每帧衰减
float rot = Main.GlobalTimeWrappedHourly * 4;
for (i = -2..2)  Draw(FullStar, GunTip, Chartreuse{A=0} * 0.35f, rotation + (shineScale + rot),
                      scale: new Vector2(1 - i*0.2f, 1 + i*0.2f) * shineScale * 3);
for (i = -2..2)  Draw(FullStar, ..., rotation - (shineScale + rot), ...);   // 反向
```
**10 次绘制（5 正转 + 5 反转）**，每份用 `(1 - i*0.2, 1 + i*0.2)` 做交叉压扁 → 五片不同长宽比的星芒互相交错，正反两组反向旋转。`0.77^n` 衰减意味着约 9 帧后不可见。

> **可复刻要点**：这把枪几乎没用"标准粒子"做持续表现，全靠**贴图重复绘制**（24 份光环 + 10 份星芒）。这比生成 34 个粒子便宜得多，且完全不占粒子预算。当你需要"武器自身在发热/充能"时，这是正解。

```csharp
if (Timer >= 30) { ... }                                        // 按住 30 帧后才开火
```

这是本篇最"省"的武器。它的全部持续表现就是**给枪贴图上色**：


## 6. Hellborn / 地狱降临 / 远程

### 实体拓扑

```
Hellborn (物品)
```

```csharp

```
`ai[2]` 为 0 时枪在手中旋转（近身伤害），非 0 时进入射击姿态。

### 近身转枪层 ✅
- **枪本体是伤害源**：`Projectile.friendly = true`、`ArmorPenetration = 25`、`localNPCHitCooldown = 4`
- 碰撞：`Colliding` 覆写为 `CalamityUtils.CircularHitboxCollision(Projectile.Center, 100, targetHitbox)` → **半径 100 像素的圆形判定**（官方未公开 ✅）
- 伤害与叠层：
  ```csharp
  if (hitTimer == 0) {
      modifiers.SourceDamage *= 0.08f;               // ✅ 官方 8%
      if (Owner.Calamity().hellbornShots < 12)       // ✅ 官方最多 12 层
          Owner.Calamity().hellbornShots++;
      hitTimer = Projectile.localNPCHitCooldown;     // 4 帧

      modifiers.SourceDamage *= 0.02f;               // 冷却中只有 2%
  }
  ```
  **注意这里有两档伤害**：4 帧内的重复命中只有 2%，且不叠层。官方日志没提这个。

- 旋转：`drawRot += 0.75f * Projectile.direction * Clamp(fade, 0.3f, 1f)`，`fade = GetLerpValue(0, 40, time)` → **起转有 40 帧的加速期**
- 绘制偏移：`drawPosition + new Vector2(0, -8).RotatedBy(drawRot * 0.6f)` → 枪不是绕自身中心转，而是**绕一个半径 8 的小圆公转**，同时自转 `drawRotation + drawRot`。这个"公转+自转"的双层旋转是手感的关键。

**每帧 2 个 `CircularSmearVFX`**（第 0 篇提到的单帧重绘型）：
```csharp
new CircularSmearVFX(Center, Color.Red       * rand(0.45,0.6), rand(-8,8), rand(1.13,1.25) * fade);
new CircularSmearVFX(Center, Color.OrangeRed * rand(0.45,0.6), rand(-8,8), rand(0.65,0.72) * fade);
```
**大红 + 小橙双层同心涂抹**，旋转角完全随机（`rand(-8,8)` 弧度）。因为每帧重生成、生命只有 2 帧，随机角度反而制造出"火焰乱窜"的闪烁，而不是规整的圆环。

**dust 双分支**（50/50）：
- 分支 A：2 个 `DustID.FireworksRGB`，半径 **35f × fade**，速度 `-3f * rand(0.5,1)`，scale `rand(0.42,0.62)`
- 分支 B：3 个 `DustID.RainbowMk2`，半径 **87f × fade**，速度 `-7f * rand(0.5,1)`，scale `rand(0.62,0.82)`
两者颜色都是 `Lerp(Orange, Red, rand(0,1))`。**两个半径差 2.5 倍 → 近身一圈密集小火 + 外圈稀疏大火**，制造纵深。

### 右键巨球 ✅
需要 `hellbornShots > 0`：
- `Owner.SetScreenshake(5f)`、`OffsetLengthFromArm -= 35f`
- **玩家自身被推开**：`Owner.velocity += shootVelocity * -0.68f`（`shootVelocity` 长度 7 → 反冲 4.76 px/frame）
- 生成 `HellbornProj`（能量球）+ `HellbornShell`（弹壳，速度 `-shootVelocity.RotatedBy(0.75f * direction)`）
- 14 组 dust（`i <= 13`）：每组 1 个 `SteampunkSteam`（白，有重力）+ 1 个 `FireworksRGB`（`Lerp(Orange, Red)`，无重力，scale `rand(0.52,0.72)`）
- 14 个 `HeavySmokeParticle`（白，`required: true`）
- 音效 `HellbornShoot`（PitchVariance 0.15）
- `cooldownTimer = Owner.itemAnimationMax * 2`

**无层数时的空枪** ✅：`DudFire` 音效、`OffsetLengthFromArm -= 8f`（轻微后坐）、`cooldownTimer = itemAnimationMax`（半冷却）、`failedShot = true`。**官方日志完全没提空枪反馈，但代码里做得很细致。**

装填音 `HellbornReload` 在 `cooldownTimer <= 18` 时播放。

### 释放法评点
Spinning 状态每帧固定生成 **2 个 smear + 2~3 个 dust**，持续、稳定、不随机爆量。这是"持续性近身武器"的正确密度——如果每帧喷 10 个，屏幕会在 3 秒内被糊死，且粒子预算全被吃光，导致右键巨球的爆发毫无表现力。

**这就是"弹匣制"武器的视觉设计范式：常态极简 → 弹匣打空时一次性倾泻。**

### "过载"警示 dust ✅

## 14 / 15. Starfleet 与 Starmada — 时机校准双子星

这两把是同一套代码，**第 1 篇里机制最精密的一对**。放在一起讲。

### 时机窗口：官方"完美帧窗未公开"的答案 ✅

```csharp
public static int perfectLeniancy    = 3;
public static int goodLeniancy       = perfectLeniancy + 6;    // = 9
public static int starburstPerfectTime = 23;

public bool naildriver  => starburstTimer 在 [23-3, 23+3]  即 [20, 26]；          // 7 帧窗口
public bool scattershot => !naildriver && starburstTimer 在 [23-9, 23+9] 即 [14, 32]; // 外圈 12 帧
```

**两把武器完全相同**：
- **完美窗口 = 7 帧**（`starburstTimer` 20~26）
- **良好窗口 = 外圈各 6 帧**（14~19 和 27~32）
- 右键按下后 `starburstTimer` 从 1 开始递增，**第 23 帧自动触发爆发**，超过 `23+9+1 = 33` 归零

也就是说：**玩家要在右键爆发（第 23 帧）前后 3 帧内按下左键**。这是一个约 0.117 秒的窗口——严格但可练。

### 右键蓄势的手臂动画（两段幂曲线）✅
```csharp
if (starburstTimer < starburstPerfectTime / 2)       // 前 11 帧：往回缩
    OffsetLengthFromArm = 25 - 12 * (1 - Math.Pow(GetLerpValue(10, 0, starburstTimer, true), 5));
else                                                  // 后 12 帧：猛推出去
    OffsetLengthFromArm = 13 + 20 * Math.Pow(GetLerpValue(11, 22, starburstTimer, true), 8);
```
- 前半段 **5 次方**：缓慢回缩（25 → 13）
- 后半段 **8 次方**：前 10 帧几乎不动，**最后 2 帧暴冲**（13 → 33）
- **这个 8 次方曲线就是"时机提示"本身**：玩家看到枪突然往前一顶，就是该按左键的瞬间。不需要 UI，不需要音效提示，全靠动画曲线。

> **这是整个第 1 篇最值得学的一处设计。** 一个 `Math.Pow(..., 8)` 就把"节奏游戏"的判定点做成了可视化的。

**几个必须注意的点：**

1. **"略失误"的散布是 0.9 弧度，比普通的 0.25 大 3.6 倍。** 官方说"略失误仍增伤但大幅扩散"——大幅到什么程度？**从 14° 炸到 52°**。这是一个非常激进的惩罚曲线：完美 3.4°、良好 51.6°、什么都不做 14.3°。**良好档比不校准还散**，只是伤害高 75%。
2. **完美档的星弹 `extraUpdates = 9`（普通 3）**，意味着完美射出的星弹**速度是普通的 3 倍**。这才是"钉枪（naildriver）"这个变量名的由来——又快又准又密。
3. **完美档有真实的玩家位移后坐**（`recoilIntensity` 55/70），`ManageRecoil()` 会直接推动 `Owner.Center`。但注意源码里有 `bool enableRecoil = false;` 硬编码 —— **位移后坐目前是被禁用的死代码**。⚠️ 复刻时需知情。
4. `dust.fadeIn = naildriver ? -0.6f : 0f` —— **负 fadeIn**，原版 Dust 里这会让粒子反向缩放，产生独特的"内爆"观感，只在完美时出现。

### 左键开火的粒子（Starfleet）✅

```csharp

    for (int i = 0; i < 4; i++)       // 每轮 4 方向 → 96 个 dust
    {

        dust = SquashDust @ gunBackPosition;

```
**96 个 dust 全部集中在 4 个方向上**（不是随机 360°）。这形成一个"十字形喷口"，比随机散射更像机械排气。完美时粒子寿命从 20 涨到 35 帧。

**B. 枪口锥形喷射**
```csharp
for (int i = 0; i < 25; i++) {
    float variance = rand(-0.7f, 0.7f);
    dust = SquashDust @ GunTipPosition;
    dust.scale    = (rand(1.4,1.8) - Math.Abs(variance)) * 3f;
    dust.velocity = velocity.RotatedBy(variance) * rand(18f, 19f) * Math.Pow(1 - Math.Abs(variance), 2);
    dust.fadeIn   = 4.75f;
}
```
**`variance` 同时控制角度、尺寸、速度**：偏离中轴越远，dust 越小（`- |variance|`）、越慢（`× (1-|variance|)²`）。→ 天然的锥形衰减，**一个随机数做三件事**。这比分别 roll 三次随机数更容易得到"物理正确"的喷射形状。

**敌人反弹**（`OnHitNPC`）的向量很有讲究：

### 视觉 ✅
**常驻（`PreDraw`）——十字脉动星芒**
```csharp
float sine      = Math.Sin(Projectile.timeLeft * 0.175f / MathHelper.Pi);
float trueSine  = MathHelper.Lerp(sine, Math.Sign(sine) * 0.5f, 0.6f);   // 方波化

```
- **两份互为倒数的压扁** → 一横一竖，叠成十字
- `trueSine` 把纯 sin 向 `±0.5` 的方波插值 0.6 → **在两个极值处停留更久**，闪烁更"硬"、更像金属反光，而不是柔和的呼吸
- `shineRot` 初始 `rand(-5, 5)`，之后 `shineRot += Math.Sign(shineRot) * 0.05f` → **朝初始符号方向单调加速旋转**，每颗子弹的旋转方向随机且越转越快

**拖尾**（每 2 帧，`time > 2` 且距玩家 < 1400）

```csharp
                true, false, shrinkSpeed: 0.8f * trailSize);
```
**`trailSize` 由当前速度决定**：速度 2→5 映射到 0→1。快时 stretch 是 `(0.8, 3.0)`（细长），慢时是 `(1, 1)`（圆点）。→ **拖尾长度自动跟随速度**，反弹减速后自然变短。这个细节让弹跳非常有物理感。

外加 1/3 概率每帧 1 个 dust（`NextBool(4) ? 91 : 264`，即 25% 概率 91 号），scale `rand(0.55, 0.7)`。

**`MakeFlash()` — 每次反弹的闪光** ✅（官方"闪光半径、白度未公开"）
```csharp
// 4 个 dust（91 或 264），速度 rand(8.5, 12)，散布 0.6
// 音效 SoundID.Item50，Pitch = -0.2f + 0.4f * bounces  ← 剩余反弹次数越多音越高
// 2 个 CustomPulse（BloomCircle）：i=0 时 scale 0→0，i=1 时 0.2→0.45，生命 9，makeLight: 0
// 5 个 SquashDust，完美均分 5 等分圆周（(TwoPi*i/5 + rot)），速度 5，scale 1.1，fadeIn 1.5，noLightEmittence
// 生成 FlashRoundFlash（damage 传 5 但不造成伤害，纯击退 AoE）
```
⚠️ **`i = 0` 那个 `CustomPulse` 的 scale 是 `0.2f * 0` = 0 → 完全不可见**。实际只有 1 个环起作用。这是循环写法的副作用，复刻时可以直接写单个环。

**5 等分而非随机**：闪光环用 5 个均分的 `SquashDust` —— 五角星形。配合 `rot = rand(-5, 5)` 的整体旋转，每次闪光朝向不同但形状一致。

> **可复刻要点**：`Pitch = -0.2f + 0.4f * bounces` 把剩余次数编码进音高（2 次→0.6，1 次→0.2，0 次→-0.2）。玩家不用看就知道弹还能弹几次。**用音高编码离散状态，比用颜色更不占视觉带宽。**

## 21. Dryad's Tear / 树妖之泪 / 远程弹药（2.2）

### 确证数值 ✅
```csharp
Projectile.ArmorPenetration = 18;          // ✅ 官方"自带 18 护穿"
public float explosionDamageMult = 1.4f;   // ✅ 官方"造成本弹 140%"
Projectile.penetrate = -1;
```

### ⚠️ 关键技术特征：这是一把**全像素化**的弹药
所有粒子生成都带 `pixelate: true`：
```csharp
GeneralParticleHandler.SpawnParticle(detach,     true);
GeneralParticleHandler.SpawnParticle(detachWave, true);
GeneralParticleHandler.SpawnParticle(trail,      true);
GeneralParticleHandler.SpawnParticle(dropTrail,  true);
```
并且用的是像素化专版 dust：`SquashDustPixelated`、`SquashDustHollowPixelated`。

**这是第 0 篇 §4 提到的审美决策的实例**：树妖之泪是自然/生命主题（`Lime` / `Turquoise` / `Aquamarine` / `Teal`），但灾厄仍然让它走像素化管线，以匹配 2.2 版本新内容的整体风格。**复刻时如果不开像素化，颜色再对也不像。**

### 双实体结构 ✅
本体（`Projectile.Center`）+ 泪滴（`dropletPosition`，一个独立追踪的位置变量，**不是另一个弹幕**）。两者各有独立的：
- 光照：`Lighting.AddLight(Center, LimeGreen * 0.4f * finalEffectMult)` 与 `Lighting.AddLight(dropletPosition, Turquoise * 0.25f * dropletScaling)`
- 拖尾粒子（本体用 `BloomCircle` + stretch `(0.25, 2.25 * Remap(speed, 7, 0.5f, 1, 0.1f))`，泪滴用另一套）

**泪滴拖尾的 stretch 计算极其精细**：
```csharp
new Vector2(0.15f * (falling ? 0.5f + dropLerp * 3 : 1) * damageMult,
            Math.Max(0.15f * lastDropletPosition.Distance(dropletPosition), 0.25f) * (1 - dropLerp * 0.2f))
```
纵向长度 = `帧间实际移动距离 × 0.15`（下限 0.25）。→ **拖尾长度严格等于本帧位移**，永远不会出现"断裂"或"重叠"的尾迹。这是做高速轨迹最正确的方法，比固定长度好得多。

### 脱离与砸落的粒子编排 ✅
`CustomColorChangeSpark` 是本武器的主力（`Lime ⇄ Turquoise` 双色渐变，`colorFadeSpeed: 5`）：
- **脱离瞬间**：3 个 `BloomCircle`（`shrinkSpeed: -0.25f`，**负值 = 反向膨胀**）+ 2 个 `ArchSmear`（左右各一，`Vector2.UnitX * 1.5f * i`）
- **砸落命中**：2~3 个 `BloomCircle`（`stretch (1, 2)`）+ 4 个 `ArchSmear`（速度 7.5 和 10.5 两档，左右对称）
- **碎屑**：5×3 = 15 个 `SquashDustPixelated`，`vel.RotatedBy(0.25f * t) * (2.5f - |t|)` → **中间快、两侧慢的三叉扇形**，中轴染 `Aquamarine`、两侧染 `Lime`
- **环形溅射**：`for (i = -dusts; i <= dusts; i++)`，位置 `NextVector2CircularEdge(10 - |i|, 10 - |i|)`，速度 `UnitX * 2f * i` → **速度与位置半径反相关的水平扇**

`reduceVisuals` 标志会削减部分循环（`(reduceVisuals ? 1 : 2)`、`(reduceVisuals ? 0 : -1)`）——**这是官方对"同屏多弹会互降伤并偏转"那条机制的视觉配套**：同屏弹多时自动降级特效，避免糊屏。

> **可复刻要点**：`reduceVisuals` 这个设计非常值得抄。当一个效果可能同屏出现十几份时，**在效果内部内置降级开关**，比事后调粒子上限优雅得多。

## 22. Claret Cannon / 深红手炮 / 无职业

### 实体拓扑
```
ClaretCannon (物品) └─ ClaretCannonProj └─ BloodstoneHealOrb × 20
```

### 全部官方数值在源码中的对应 ✅（这把武器是交叉验证的最佳样本）

```csharp
public override void OnHitNPC(NPC target, NPC.HitInfo hit, int damageDone)
{
    int cooldown = 600;                                       // 10 秒 ✅
    if (player.HeldItem.ModItem is IClaretCannonInstance cooldownWeapon)
        cooldown = cooldownWeapon.CooldownMax;

    target.AddBuff(ModContent.BuffType<Laceration>(), cooldown / 2);   // 裂伤 300 帧 = 5 秒 ✅
    target.AddBuff(BuffID.BetsysCurse, cooldown);                     // 贝蒂诅咒 600 帧 = 10 秒 ✅

    if (Projectile.penetrate == -1) return;

    for (var i = 0; i < 20; i++)                                       // 20 血球 ✅
        Projectile.NewProjectile(..., -Projectile.velocity.SafeNormalize(Vector2.Zero).RotatedByRandom(1)
            * Main.rand.NextFloat(2.75f, 5.25f), ProjectileType<BloodstoneHealOrb>(), 20, ...);
        //                                                    ↑ 20 帧 = 0.33 秒药水病削减 ✅

    // 就地转为爆炸判定
    Projectile.Size      = new Vector2(352);                           // ← 官方"爆炸大小未公开"的答案
    Projectile.penetrate = -1;
    Projectile.extraUpdates = 0;
    Projectile.timeLeft  = 2;
    Projectile.velocity *= 0;
    Projectile.damage   /= 2;                                          // 50% ✅
}
```

**官方日志的 5 个数字（10 秒 / 50% / 裂伤 5 秒 / 贝蒂诅咒 10 秒 / 20 血球 / 0.33 秒）在源码里全部一一对应。**而官方标为"未公开"的爆炸尺寸，答案是 **352×352 像素的正方形判定框**（22×22 格）。

### 爆炸的实现方式很特别 ⚠️
它**不生成新的爆炸弹幕**，而是把子弹自己原地撑大：`Size = new Vector2(352)`、`penetrate = -1`、`timeLeft = 2`、`velocity = 0`、`damage /= 2`。

**这是最省资源的爆炸做法**：零新实体、零同步开销。代价是爆炸判定框是**正方形**而非圆形——贴着爆炸边角的敌人也会被打到。复刻时若追求圆形判定需自己覆写 `Colliding`。

### 视觉 ✅
`OnKill` 里（`penetrate != -1` 时直接 return，所以**只有爆炸态才有特效**）：
```csharp
SoundEngine.PlaySound(PerfLargeDeath  { Volume = 0.5f });
SoundEngine.PlaySound(BloodPactCrit   { Volume = 0.5f });
float particleScale = 8f;
new CustomPulse(Center, Zero, 血腥色, "DetailedExplosion",     Vector2.One, rand(-15,15), 0.16f*8/5, 0.87f*8/5, 15, false);
new CustomPulse(Center, Zero, 血腥色2, "DustyCircleHardEdge",  Vector2.One, rand(-15,15), 0.03f*8/5, 0.155f*8/5, 40);
```
即 **`DetailedExplosion` 从 0.256 涨到 1.392（生命 15 帧，快）** + **`DustyCircleHardEdge` 从 0.048 涨到 0.248（生命 40 帧，慢）**。
**快而大的主爆 + 慢而小的余环**，两条不同速度的曲线叠加 → 爆炸有"核心闪现 + 尘埃缓散"的层次。只用了 2 个粒子。

**血腥模式判断贯穿全武器**：`!ChildSafety.Disabled ? Color.CornflowerBlue : Color.DarkRed`。注意逻辑——`ChildSafety.Disabled` 为 **false**（即启用血腥过滤）时用矢车菊蓝。`PreDraw` 里也是：过滤开启时整个弹体强制染 `Color.CornflowerBlue`，关闭时走默认绘制。

伤害类型是 `AverageDamageClass.Instance` ✅ —— 这就是"无职业"的实现。

### 释放法评点
爆炸只有 2 个粒子，但**血球有 20 个**。视觉重心被完全放在"战利品"上而不是"爆炸"上。这符合武器的定位：它是一个 10 秒 CD 的资源生成器，玩家真正关心的是那 20 颗球。

**如果反过来做——爆炸 50 个粒子、血球做成不可见的治疗数字——武器的手感会完全变味。**

> **可复刻要点**：载具/自由转向类武器，拖尾必须用"速度插值型"粒子。用固定速度的火花，转向时会出现明显的"断裂尾迹"。
