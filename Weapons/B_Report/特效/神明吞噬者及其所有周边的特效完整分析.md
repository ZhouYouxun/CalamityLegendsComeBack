# 神明吞噬者（Devourer of Gods）重做后视觉与弹幕完整分析

> **源码基准**：本报告按当前 `CalamityMod` 源码静态核对，不以旧版视频、Wiki 或旧报告为准。
>
> **路径规则**：文中所有本地路径均从 `ModSources\` 起算；例如 `ModSources\CalamityMod\Projectiles\Boss\DoGFire.cs`。需要复制/参考资产时，只需从自己的 `ModSources` 文件夹继续进入即可，不暴露用户目录。
>
> **范围**：重做后的 DoG Boss 本体、天空与 RenderTarget、Boss 直接生成的全部 `DoG*` 弹幕、死亡效果，以及这些系统实际调用的粒子、Shader、纹理和声音。文末另列“可复用接口”。它不是“所有 DoG 后武器的总表”：后 DoG 武器很多，但不应把它们误说成 Boss 重做本体的一部分。

---

## 0. 结论：旧报告哪里对，哪里不够

旧报告抓对了几个关键点：`DoGTeleportRift`、`DoGFire`、`DoGRiftCrack`、`DoGDistortionMetaball`，以及紫—青配色与通用粒子。这些都是真正的 DoG 视觉语言。

但“完整分析”这个标题并不成立，主要缺口有四类：

1. **没有把 Boss 重做看成一套分层渲染系统。** DoG 的核心不只是 `GeneralParticleHandler`；`DoGSky`、`DoGVisualsManager`、多张 RenderTarget、背景裂隙、前景扭曲风、元球采样共同决定了“世界被撕开”的感觉。
2. **漏掉 Boss 本体逐段绘制。** 头、身体、尾巴都有阶段纹理、紫/青双 glowmask；Rift Dash 还有 `GodSlayerDashJaw` 的双层加法绘制；死亡时三者都会进入 `CalamityMod:Dissolve`。
3. **没有逐颗解释 Boss 直接发射的弹幕。** 当前 Boss 直接链路包含 9 个 `DoG*` projectile 类型；其中激光墙又分普通格栅、中央巨束、GFB 环形变体，传送裂隙还会二次生成 25 条裂缝。
4. **把“可用粒子”写成了脱离调用链的配方。** 读者需要知道准确的 C# 类型、命名空间、构造参数、纹理路径、在哪一层画，以及哪些东西是可直接 `new`、哪些只能走系统/Shader 入口。

因此，本重写按“视觉系统 → 本体 → 攻击生成链 → 每个弹幕 → 可调用资源”的顺序组织。这样既能还原重做后的设计，也能实际用于新武器或新 Boss。

## 2. 统一视觉语法：颜色、纹理与层级

### 2.1 色彩不是一个“DoGColor”常量

`DevourerofGodsHead.SpecialMoveColor` 是最接近“动态 DoG 色”的公开属性：

```csharp
Color color = DevourerofGodsHead.SpecialMoveColor;
```

它位于 `ModSources\CalamityMod\NPCs\DevourerofGods\DevourerofGodsHead.cs`，在文字特效启用时以 `SmoothStep(sin(time * 2))` 在 `Color.Fuchsia` 与 `Color.Cyan` 间往返；关闭文字特效时退化为 `Color.Cyan`。这适合普通攻击的动态点缀，但它**不是**整个 Boss 每一个效果的统一颜色。

真正的重做色板至少分为：

| 视觉职责 | 内部颜色名 | 实际用处 |
|---|---|---|
| 高能边缘 | `Color.Fuchsia` | P2 紫色 glowmask、激光墙起始色、Rift Dash 颚部外层 |
| 冷色能量 | `Color.Cyan` | P2 青色 glowmask、激光墙终末色、被动火焰主体 |
| 深裂隙 | `DoGSky.DoGTwlight` | 传送裂隙、爆裂 `CustomPulse`、裂隙天空深色层 |
| 裂隙亮部 | `DoGSky.DoGLightBlue` | 裂隙火花/光团的候选色 |
| 白色核 | `Color.White` | 十字星、裂纹 Shader 亮端、`StrongBloom` 核、内层激光 |
| 攻击紫火 | `Color.Purple` / `Color.Fuchsia` | `DoGFire` 主体/核心；并非单纯 Fuchsia |

`DoGSky.DoGTwlight` 的拼写就是 **Twlight**，调用时不要写成 `Twilight`。

### 2.2 四种不同的“光”层

1. **普通 alpha 贴图**：Boss 本体、基础弹幕。
2. **`BlendState.Additive` 加法层**：裂隙十字星、Rift Dash 特殊颚、部分 bloom；亮度会累加，适合能量核，不能拿来画黑色实体。
3. **Primitive trail**：`PrimitiveRenderer.RenderTrail(...)` 生成连续带状几何，`DoGFire` 和 `DoGRiftCrack` 的主体都属于这一层。
4. **Shader / RenderTarget**：裂缝、天空、前景畸变。这里不是“多画一张紫图”，而是先把背景/前景画进 RenderTarget，再让 shader 取样并扭曲。

这四层应按职责叠加。若只往一个 projectile 上堆大量 `SparkParticle`，只能得到亮，不会得到 DoG 的“裂开空间”。

## 3. Boss 战场本身：天空、现实裂纹与屏幕畸变

### 3.1 `DoGSky`：背景裂隙不是 projectile

**内部类型**：`CalamityMod.Skies.DoGSky`
**路径**：`ModSources\CalamityMod\Skies\DoGSky.cs`

`DoGSky.Draw(...)` 按以下顺序绘制：

1. `DrawDistortionWinds`：`CalamityShaders.DoGDistortionWindsShader` 的风状噪声；
2. `DrawRollingBackgroundFog`：`CalamityShaders.DoGBackgroundFogShader` 的滚动雾；
3. `DrawRiftAura`：`CalamityShaders.DoGRiftAuraShader` + 裂隙 aura 纹理；
4. `DrawRealityCracks`：`CalamityShaders.DoGRealityCrackShader` + 破玻璃纹理；
5. `DrawDistortionRift`：把裂隙臂绘至目标，再用元球边缘 shader 组合。

这说明 DoG 的“大背景裂缝”不应通过 `Projectile.NewProjectile` 复制。若自己的 Mod 需要同等级背景，应参考/复用天空或场景系统；若只做单次武器命中，改用第 5 节的 `DoGTeleportRift` 或 `DoGRiftCrack` 更合理。

### 3.2 `DoGVisualsManager`：让扭曲真正看到屏幕内容

**内部类型**：`CalamityMod.Systems.Graphic.DoGVisualsManager`
**路径**：`ModSources\CalamityMod\Systems\Graphic\DoGVisualsManager.cs`

它维护三个关键 RenderTarget：

| 内部属性 | 内容 | 被谁消费 |
|---|---|---|
| `DistortionRiftBackgroundContentsTarget` | 裂隙内的背景内容 | `DoGSky` 的巨大背景裂隙 |
| `DistortionRiftPrimitivesTarget` | 裂隙臂 Primitive | `DoGSky.DrawDistortionRift` |
| `DistortionForegroundContentsTarget` | 玩家/弹幕后面的前景画面 | `DoGDistortionMetaball` 的屏幕扭曲 |

`DoGDistortionMetaball` 活跃时，管理器会把前景云雾和风绘入 `DistortionForegroundContentsTarget`，之后元球边缘 shader 以该目标为底图扭曲。因此：**DoG 的扭曲元球不是一枚紫色烟雾粒子；它是“用元球遮罩扭曲一张屏幕缓存”。**

### 3.3 可直接参考的 Shader 名与纹理名

| 名称 | 内部调用名 | 文件路径 | 使用方式 |
|---|---|---|---|
| 现实裂纹 | `CalamityShaders.DoGRealityCrackShader` | `CalamityMod\Effects\DoGRealityCrackShader.fx` | 读取 `opacityCutoffValue`、`fadeoutPower`、`overallOpacity`、`darkerPixelColor`、`brighterPixelColor` 后 `Apply()` |
| 传送门 | `GameShaders.Misc["CalamityMod:DoGPortal"]` | `CalamityMod\Effects\ScreenShaders\DoGPortalShader.fx` | `.UseOpacity(scale).UseColor(Color.Cyan).UseSecondaryColor(Color.Fuchsia).Apply()` |
| 裂隙 aura | `CalamityShaders.DoGRiftAuraShader` | `CalamityMod\Effects\DoGRiftAuraShader.fx` | 由 `DoGSky.DrawRiftAura` 使用 |
| 背景雾 | `CalamityShaders.DoGBackgroundFogShader` | `CalamityMod\Effects\DoGBackgroundFogShader.fx` | 由天空与前景目标使用 |
| 扭曲风 | `CalamityShaders.DoGDistortionWindsShader` | `CalamityMod\Effects\DoGDistortionWindsShader.fx` | 由天空与前景目标使用 |
| 发光裂玻璃 | `CalamityMod/ExtraTextures/CrackedGlass_Glowing` | `CalamityMod\ExtraTextures\CrackedGlass_Glowing.png` | `DoGTeleportRift.PreDraw` 的裂纹贴图 |

## 4. Boss 本体：三段虫体也各自是一套特效

### 4.1 头部 `DevourerofGodsHead`

**内部类型**：`DevourerofGodsHead`
**路径**：`ModSources\CalamityMod\NPCs\DevourerofGods\DevourerofGodsHead.cs`

`PreDraw` 的实际层序是：基础头图 → 两片下颚和白色下颚 glow →（Rift Dash 时）特殊颚 → 头部紫 glowmask → 头部青 glowmask →（死亡时）结束 dissolve shader 区域。

关键资源与内部 `Asset<Texture2D>` 名称：

| 内部资产字段 | 对应资源路径 |
|---|---|
| `Texture_Glow_Purple` / `Texture_Glow_Cyan` | `CalamityMod\NPCs\DevourerofGods\DevourerofGodsHead_Glow_Purple.png`、`..._Glow_Cyan.png` |
| `TextureP2` | `CalamityMod\NPCs\DevourerofGods\DevourerofGodsHead_Jawless_P2.png` |
| `TextureP2_Glow_Purple` / `TextureP2_Glow_Cyan` | 同目录 `...Jawless_P2_Glow_Purple.png`、`..._Cyan.png` |
| `JawTexture` / `JawTexture_Glow` | `...\DevourerofGodsHead_Jaw.png`、`..._Jaw_Glow.png` |
| `JawTextureP2` / `JawTextureP2_Glow` | `...\DevourerofGodsHead_Jaw_P2.png`、`..._Jaw_P2_Glow.png` |
| `GodSlayerDashJawTexture` | `CalamityMod\NPCs\DevourerofGods\GodSlayerDashJaw.png` |

其中 `GodSlayerDashJawTexture` 不是普通 glowmask：当 `GodSlayerDashJawFadeProgress > 0.02f` 时，以 `BlendState.Additive` 同位置画两遍——`Color.Fuchsia`、`scale * 1.6f` 的较大外层，加 `Color.Cyan`、`scale * 1.3f` 的内层。这是 Rift Dash 最有辨识度的“嘴部能量撕裂”，可作为冲刺武器的直接参考。

### 4.2 身体与尾部 `DevourerofGodsBody` / `DevourerofGodsTail`

**内部类型与路径**：

- `DevourerofGodsBody`：`ModSources\CalamityMod\NPCs\DevourerofGods\DevourerofGodsBody.cs`
- `DevourerofGodsTail`：`ModSources\CalamityMod\NPCs\DevourerofGods\DevourerofGodsTail.cs`

两者不是只画原图。P2 活跃时，身体每段会先画 P2 基础图，然后按状态分别叠加：

- `TextureP2_Glow_Purple`，色为 `Lerp(White, Fuchsia, 0.5f)`；
- `TextureP2_Glow_Cyan`，色为 `Lerp(White, Cyan, 0.5f)`。

这让虫体不是“一整条固定渐变”，而是根据被动/攻击状态选择不同 glow 层。要模仿，应保留“基础实体 + 两张分离颜色 glowmask”的结构，不能把两张图预烘焙成一张。

### 4.3 死亡溶解

头、身、尾都会读取 `CalamityDrawParameterNPC.DoGDeathAnimationTimer`，以 `GameShaders.Misc["CalamityMod:Dissolve"]` 绘制。关键参数为：

```csharp
dissolveShader.Shader.Parameters["dissolveIntensity"]
    .SetValue(CalamityDrawParameterNPC.DoGDeathAnimationTimer / 600f);
dissolveShader.Shader.Parameters["transitionColor"]
    .SetValue(DevourerofGodsHead.SpecialMoveColor.ToVector4());
```

对应 shader 文件为 `ModSources\CalamityMod\Effects\DoGDisintegration.fx`。这是“身体被动态紫青边缘吞噬”的系统效果，和 `DoGDeathBoom` 的中心爆炸是两件不同的事。

## 5. Boss 直接生成链：攻击状态到所有弹幕

生成总入口在：`ModSources\CalamityMod\NPCs\DevourerofGods\DevourerofGodsHead.cs`。

```text
DevourerofGodsHead
├─ DoGP1EndPortal                 P1 转场/退场门
├─ DoGTeleportRift
│  └─ DoGRiftCrack ×25            裂隙爆开时的程序裂缝
├─ DoGFire                        被动或攻击火焰弹
├─ DoGLaserWalls                  格栅/交叉/环形激光墙
├─ DoGLaserWallsBigBeam           激光墙的中央巨束
└─ DoGDeathBoom                   死亡中心爆炸

DoGBeamPortal
└─ DoGBeam                        独立传送门射线链
```

最后一条 `DoGBeamPortal → DoGBeam` 也在 Boss projectile 家族中，但不是上面头部 AI 当前直接生成的常规链；仍应在“所有周边弹幕”中保留，不能遗漏。

## 6. 弹幕逐颗拆解（内部名、路径、绘制与调用）

### 6.1 `DoGTeleportRift`：传送裂隙与出场爆裂

**内部类型**：`CalamityMod.Projectiles.Boss.DoGTeleportRift`
**路径**：`ModSources\CalamityMod\Projectiles\Boss\DoGTeleportRift.cs`
**生成**：`Projectile.NewProjectile(..., ModContent.ProjectileType<DoGTeleportRift>(), ..., ai0: NPC.whoAmI)`。

它是无伤害、原图为 `InvisibleProj` 的效果 projectile。它的 `ai[0]` 是 DoG 头部索引；`ai[1]` 是 `Timer`；`ai[2]` 是 `CrackScale`。因此不是“发一个裂隙以后随便改 `scale`”——生命周期和 Boss 关联。

**蓄力阶段（按 `RiftLifetime / 3` 的间隔触发）：**

- `SparkParticle` ×12，向外发射；
- `SquishyLightParticle` ×8，向外发射；
- `CustomPulse`，纹理名 `CalamityMod/Particles/ShineExplosion2`；
- `CalamityUtils.AddScreenshakeAt(...)`；
- 裂缝暴露度 `CrackExposure` 与尺寸 `CrackScale` 逐段增加。

**爆裂阶段 `SpawnExplosionVisuals()`：**

- `DoGRiftCrack` ×25；
- `DoGDistortionMetaball.SpawnParticle`：中心 35 个巨大方形 + 15–20 个飞散元球；
- `SparkParticle` ×25、`SquishyLightParticle` ×20；
- `CustomPulse`：`PlasmaExplosion` ×3、`ShineExplosion1` ×1、`ShineExplosion2` ×1；
- `StrongBloom` ×1；
- `BreakSound` 与 14 强度屏震。

**绘制入口 `PreDraw`：**

1. 加法混合下以 `CalamityMod/Projectiles/StarProj` 画横、竖十字星；真裂隙额外画深裂隙色的内层十字。
2. `CalamityShaders.DoGRealityCrackShader` 处理 `CrackedGlass_Glowing`；真裂隙画 3 个旋转裂纹，假裂隙只画 1 个。
3. 非爆裂期再画 `CalamityMod/Particles/BloomRing`，半径从 8 收至 0。

**假裂隙**：`FakeRift = true` 是 GFB 的干扰分支；它不产生 25 条裂缝、扭曲元球和粒子爆发，结束时只产生 3 个 `PulseRing`。做仿制时，假裂隙应削弱“信息量”，而不是仅把颜色调白。

### 6.2 `DoGRiftCrack`：25 节点的程序裂缝

**内部类型**：`CalamityMod.Projectiles.Boss.DoGRiftCrack`
**路径**：`ModSources\CalamityMod\Projectiles\Boss\DoGRiftCrack.cs`
**调用**：通常由 `DoGTeleportRift` 生成：

```csharp
Projectile.NewProjectile(source, center, crackLength,
    ModContent.ProjectileType<DoGRiftCrack>(), 0, 0f, owner,
    ai0: 0f, ai1: riftWidth);
```

不要误解旧报告中的“可传颜色”。这个版本的 `DoGRiftCrack` 没有颜色 ai 参数：`ai[0]` 是 `Timer`，`ai[1]` 是 `MaxWidth`；颜色固定为 `Projectile.GetAlpha(Color.White)`。

首次 AI 会生成 `Vector2[25] CrackPoints`：第一个点是中心，第二点由 projectile velocity 加随机偏移决定，后续点沿前两点方向延展并随机转向。持续 30 tick，`Projectile.scale` 从 1 线性降至 0。`PreDraw` 使用：

```csharp
PrimitiveRenderer.RenderTrail(CrackPoints,
    new(CrackWidthFunction, CrackColorFunction, null, false));
```

它同时被 `DoGDistortionMetaball.AnythingToDraw` 自动扫描，并通过元球系统被纳入前景畸变。换言之：**生成 `DoGRiftCrack` 就会带上裂线和扭曲联动；不需要手动把它塞进 `DoGDistortionMetaball.Particles`。**

### 6.3 `DoGFire`：双层像素火焰带

**内部类型**：`CalamityMod.Projectiles.Boss.DoGFire`
**路径**：`ModSources\CalamityMod\Projectiles\Boss\DoGFire.cs`
**调用**：`ModContent.ProjectileType<DoGFire>()`。`ai[0] == 2f` 时 `IsAPassiveFireball` 为真。

它没有本体 sprite，`PreDraw` 直接返回 false；视觉全部来自 `IPixelatedPrimitiveRenderer.RenderPixelatedPrimitives`：

| 层 | Shader / 纹理 | 被动火焰 | 攻击火焰 |
|---|---|---|---|
| 外层主体 | `GameShaders.Misc["CalamityMod:ImpFlameTrail"]` + `CalamityMod/ExtraTextures/Trails/ScarletDevilStreak` | `Color.Cyan`，最大 72px | `Color.Purple * 1.3f`，最大 72px |
| 内层核心 | 同 shader + `CalamityMod/ExtraTextures/Trails/SylvestaffStreak` | `Color.SkyBlue`，最大 24px | `Color.Fuchsia`，最大 64px |

外层随轨迹做宽度脉动；内层更短、更亮。AI 中另有两类拖尾：

- `DustID.TintableDustLighted`：约 1/12 概率，每次 2 个；
- `HeavySmokeParticle`：约 1/2 概率，每次 3 个，反向速度。

命中或消失会产生 12 个 `TintableDustLighted`。所以若复刻其视觉，最重要的是**两条不同纹理/宽度的 Primitive trail**，不是烟雾。

### 6.4 `DoGLaserWalls`：普通格栅、斜格栅与环形墙

**内部类型**：`CalamityMod.Projectiles.Boss.DoGLaserWalls`
**路径**：`ModSources\CalamityMod\Projectiles\Boss\DoGLaserWalls.cs`
**调用**：`ModContent.ProjectileType<DoGLaserWalls>()`；AI 参数含义：`ai[0] = attackSpeed`、`ai[1] = laserDist`、`ai[2] = laserType`。

`laserType` 0–5 决定横竖/45°/交叉的排布，`6` 是 GFB 环形版本。它不是一个“整屏单线”，而是对每个网格位置绘制线段：

- 蓄力时画 1 层 `BloomLineThick`；
- 发射后，对同一条线增加 4 层黑色 `LineThick`，制造暗边与深度；
- `drawColor` 在攻击后从 `Color.Cyan` 向 `Color.Magenta` 过渡；
- `laserFX` 控制显隐，`sine` 让宽度脉动；
- 环形变体直接用 `CalamityMod/Particles/BloomRingThinLarge` 叠多个同心环。

使用的纹理内部路径：

- `CalamityMod/Particles/BloomLineThick`
- `CalamityMod/Particles/LineThick`
- `CalamityMod/Particles/BloomRingThinLarge`（仅 type 6）

声音为 `CalamityMod/Sounds/Custom/DoGLaserWallSpawn`（预警）与 `.../DoGLaserWallLightAttack`（发射）。

### 6.5 `DoGLaserWallsBigBeam`：中央巨束

**内部类型**：`CalamityMod.Projectiles.Boss.DoGLaserWallsBigBeam`
**路径**：`ModSources\CalamityMod\Projectiles\Boss\DoGLaserWallsBigBeam.cs`
**调用**：`ModContent.ProjectileType<DoGLaserWallsBigBeam>()`，`ai[0] = attackSpeed`，`ai[2] = laserType`。

这颗弹幕在目标远方 3000px 处设置 `beamStart`，向目标贯穿。视觉和普通墙同源（`BloomLineThick` 主光 + `LineThick` 黑边），但 `Projectile.scale` 初始为 2，传奇模式为 6；攻击后会叠到 `4 * scale` 层。颜色从 `Color.Magenta` 转到 `Color.Cyan`，命中线宽为 `30 * scale`。

声音内部路径：`CalamityMod/Sounds/Custom/DoGLaserWallBigAttack2`。因此要做“DoG 中央审判束”，应参考本类，而不要使用玩家武器的 `FriendlyLaserWallBeam`——后者不是 Boss 攻击。

### 6.6 `DoGP1EndPortal`：P1 结束/转场门

**内部类型**：`CalamityMod.Projectiles.Boss.DoGP1EndPortal`
**路径**：`ModSources\CalamityMod\Projectiles\Boss\DoGP1EndPortal.cs`
**调用**：`ModContent.ProjectileType<DoGP1EndPortal>()`；`ai[1]` 为 `TimeCountdown`。

它在 `DrawBehind` 中加入 `overWiresUI`，保证门在玩家和世界之上。`PreDraw` 用 `VoronoiShapes` 噪声图作为源纹理：

```csharp
GameShaders.Misc["CalamityMod:DoGPortal"]
    .UseOpacity(Projectile.scale)
    .UseColor(Color.Cyan)
    .UseSecondaryColor(Color.Fuchsia)
    .Apply();
```

噪声图路径为 `CalamityMod/ExtraTextures/GreyscaleGradients/VoronoiShapes`。这是可复用的“程序噪声门”模板；只复制一张静态 portal PNG 无法得到该流动感。

### 6.7 `DoGDeathBoom`：死亡中心冲击

**内部类型**：`CalamityMod.Projectiles.Boss.DoGDeathBoom`
**路径**：`ModSources\CalamityMod\Projectiles\Boss\DoGDeathBoom.cs`
**继承**：`BaseMassiveExplosionProjectile`。

这是一颗由死亡 AI 生成的零伤害中心爆炸 projectile。它的实际形状/尺寸逻辑由基类提供，DoG 类负责把它放在超远屏幕检查范围内。不要把它和第 4.3 节的全身 dissolve、或第 6.1 节的裂隙爆裂混为一谈：死亡画面是“三条并行视觉线”同时发生。

### 6.8 `DoGBeamPortal`：独立的射线传送门

**内部类型**：`CalamityMod.Projectiles.Boss.DoGBeamPortal`
**路径**：`ModSources\CalamityMod\Projectiles\Boss\DoGBeamPortal.cs`
**子弹幕**：`DoGBeam`，见下一节。

它是一个完整的“门先开、后喷射线”容器。其 AI 在发射阶段通过：

```csharp
Projectile.NewProjectile(Projectile.GetSource_FromThis(), Projectile.Center,
    velocity, ModContent.ProjectileType<DoGBeam>(), 0, 0f,
    Main.myPlayer, Projectile.damage, 0f);
```

生成 `DoGBeam`。门的音效调用 `SoundID.Item92` / `SoundID.Item33`；若做可读性强的门炮，应按“蓄力门体 → 明确发射音 → 子弹幕”拆成两类 projectile，而不是让一颗 beam 同时承担全部动画。

### 6.9 `DoGBeam`：传送门发出的射线

**内部类型**：`CalamityMod.Projectiles.Boss.DoGBeam`
**路径**：`ModSources\CalamityMod\Projectiles\Boss\DoGBeam.cs`

它是 `DoGBeamPortal` 的子 projectile；调用内部名固定为 `ModContent.ProjectileType<DoGBeam>()`。它使用自己的两帧 sprite（`Main.projFrames[Type] = 2`），每 5 tick 换帧，旋转沿速度方向加 `PiOver2`；不是 Primitive trail 或 shader beam。

生成时门体把伤害暂存到 `ai[0]`，本体在 `timeLeft == 950` 时才读取伤害，前 10 tick 不造成伤害；末尾 30 tick 把伤害清零并按 `GetAlpha` 淡出。`ai[1]` 是飞行计时器：第 31–119 tick 会以 `(velocity * 20 + targetDirection) / 21` 的方式缓慢转向最近玩家。也就是说，它的视觉要点是青蓝发光两帧弹，而玩法要点是“从门射出、短暂安全、有限时间转向”，不能误归类为 DoG 的激光墙。

分析或改动此链时，必须同时检查门体与射线，不能只搜索 `DoGBeam.cs` 后认定它是独立攻击。

GeneralParticleHandler.SpawnParticle(particle);

### `DoGDistortionMetaball` 不是 `Particle`

**内部类型**：`CalamityMod.Graphics.Metaballs.DoGDistortionMetaball`
**路径**：`ModSources\CalamityMod\Graphics\Metaballs\DoGDistortionMetaball.cs`

它的内部数据类是 `DistortionParticle`，生成方法是：

```csharp
DoGDistortionMetaball.SpawnParticle(center, velocity, size,
    square: false, rotation: 0f);
```

`square: true` 用于裂隙中心的巨大方块破面；默认圆形用于向外飞散的畸变团。它的 `DrawLayer` 是 `GeneralDrawLayer.AfterProjectiles`，但结果还会采样 `DoGVisualsManager.DistortionForegroundContentsTarget`，因此这是“弹幕后方/玩家前方的屏幕畸变层”，不是普通贴图。

## 9. 实作注意事项

1. **先区分“内部类型名”和“资源路径”。** `DoGFire` 是 C# projectile 类型；`CalamityMod/ExtraTextures/Trails/ScarletDevilStreak` 是它传给 shader 的纹理路径，两者不可互换。
2. **Boss projectile 的 `ai[]` 已被占用。** 例如 `DoGRiftCrack.ai[1]` 是宽度，`DoGLaserWalls.ai[1]` 是间距。包装/复用时随意覆写 ai 会直接改变行为或视觉。
3. **保持层级。** Additive 绘制完必须恢复 `BlendState.AlphaBlend`；`DoGTeleportRift` 的 `PreDraw` 已给出了安全范例。
4. **不要把 `DoGRiftCrack` 写成“紫色或品红二选一”。** 当前源码里裂线为白色并由元球/裂隙背景染出空间感；颜色信息主要来自环境层与周围 burst。
5. **光敏设置需要尊重。** `DoGTeleportRift`、`DoGLaserWalls` 等都在 `CalamityClientConfig.Instance.Photosensitivity` 下压低亮度。新效果若直接借鉴这套风格，也应提供同样的降闪烁处理。

## 11. 最终理解

神明吞噬者重做后的特效并非“紫青粒子包”。它有一条明确的视觉因果链：**天空先失真 → 裂隙在空间中蓄压 → 实体虫体以分离 glowmask 与特殊颚获得攻击态 → projectile 用 Primitive 或多层线条建立运动与危险区 → 粒子和 bloom 只在关键节点放大冲击 → RenderTarget/元球把局部事件重新作用回屏幕。**

所以，若以后要借 DoG 风格，最值得复制的是这条因果链与层级关系；粒子数量、颜色和某一张贴图都只是它的局部表达。
